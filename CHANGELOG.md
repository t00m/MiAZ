## [0.3.0] - Unreleased

### Added

- **MiAZDoctor can check the repository when it opens.** A switch in Repository Settings, Settings, under Repository health: "Check the repository when it opens". Off by default, and stored with the repository rather than with the installation, at `.conf/plugins/MiAZDoctor/conf/doctor.json`, so a repository being cleaned up gets the check while an archive nobody touches does not. It runs on the `workspace-loaded` signal, which fires at startup and again on every repository switch, so each repository is checked against its own answer. The check itself is the one the menu entry runs, on a worker thread, 1.2 seconds for 1322 documents, so nothing waits for it. What it does with the result depends on what it found: a problem opens the report, because a problem is what stops documents being filed or found, and anything else is a toast carrying the verdict and an Open button, because drift worth cleaning is not worth a window in front of the workspace. A repository in good order says so in a toast: a check that finds nothing and says nothing reads the same as a setting that does not work. `srvdlg.show_toast` gained an optional button and returns the toast it made.

- **A document preview in the workspace.** `MiAZDocPreview` shows the first page of the selected document, so a filename that says nothing can be settled without opening the file in another application. It is a toggle in the header bar, off by default, and it comes up from the bottom as an `Adw.BottomSheet` rather than in from the side: a document list needs its width and a phone has none to give, while height is the one thing every screen has. The sheet is not modal, so the list stays usable and the preview follows the row being clicked, and it has a drag handle, so it can be pulled shut. Closing it that way releases the header bar toggle, which is otherwise the only thing that knows. It follows the selection and does nothing at all while it is closed: no file is read, no page is rendered. Two buttons make the page bigger and smaller. Zooming renders the page again at the new width instead of stretching the image already on screen, so zooming in shows more of the page rather than bigger pixels, and since the render cache is keyed by width, a size already seen comes back instantly. The heading is the concept and the line under it is the date, because that is what names a document; the filename is what it is filed as, and it stays as the tooltip. The rendering itself is `MiAZ/backend/thumbnails.py`, which has no GTK in it and is therefore testable without a display: `pdftoppm` writes the first page of a PDF into `~/.MiAZ/var/cache/thumbnails`, an image file is its own preview, and anything else has no preview and says so. The cache key is the content hash, not the path, so a renamed document keeps the image it already has and an edited one gets a fresh render; `_digest` in `duplicates.py` became the public `file_digest` for it. The render runs in a worker with a token per request, so a fast walk down the list cannot leave a late result painting the wrong page.
- **The preview is in the rename dialog too**, which is where a document most needs reading: the fields are filled in from what the page says. It comes up from the bottom when the Preview button asks for it, so the seven fields keep the full width of the dialog and nothing is read until someone wants to look: most renames never need the page. The sheet can be dragged shut, and doing so releases the button. Preview used to open the document in an external viewer; that action moved into the preview itself, next to the zoom buttons, where it also serves the workspace sheet, since the preview is the first page and reading the rest still means opening the document properly.
- **A Grid view of the workspace**, the documents as pages rather than as rows, the way a file manager shows icons. A cell is the whole filename read the way a letter is read: the country flag, the date and the group above the page, then the line "Purpose sent by Sender", and under the page the concept, centred. The four values that name a document, the group, the purpose, the sender and the concept, are bold and undimmed; the date and the words joining them are not. The recipient has no line of its own: on a grid of pages it was small print nobody read, and it is in the tooltip with the keys. Descriptions are on the cell and the keys are one hover away, since a grid is for recognising a document, not for reading its filing codes. Pages start at 256px and go from 128 to 512; the page is rendered again at whatever size is being shown, so a bigger icon is more of the page and not a stretched small one. The rendering is the same backend the preview uses, and its cache is keyed by width, so a size already seen comes back instantly. Like the timeline it is a pure view over the filtered set and carries no model until its page is on screen, so a repository of 1300 documents costs nothing while the document list is the page being looked at. Two details were measured rather than assumed. `Gtk.GridView` keeps a buffer of about 32 rows, so the number of cells it builds is 32 times max-columns whatever the window actually shows: the first attempt set 24 columns and built 769 cells, and queued 769 pages to render, for a screen holding a dozen. Max-columns is now derived from the icon size and capped at 12, which is 321 cells at 256px. And a queued render is abandoned if it is no longer wanted, checked twice: the cell may have been recycled onto another document, or the grid may have changed size, and only the second check makes resizing responsive, because resizing rebinds by replacing the model and that throws the old cells away rather than updating them.
- **A Timeline view of the workspace**. It reads the same filtered model the document list does, sorted by date ascending, one card per document with its date, concept, sender, recipient and field pills. It is a view and nothing else: the sidebar keeps doing every bit of the filtering, so narrowing to one sender or one year is the same gesture it always was. It does its work only while it is the page on screen, and that is not a detail: an `Adw.ViewStack` measures the pages it is not showing, which was enough to make the timeline build a row per document, each one rendering a PDF on a thread of its own, while the user sat on the document list. On a repository of 1300 documents, widening the filter to everything froze the window for twelve seconds. The page now carries no model until it is shown and gives it back when it is switched away from, which puts the same action at 0.7 seconds with the timeline open and at nothing at all with it closed. An `Adw.ViewStack` maps a page the first time it is shown and never unmaps it again, so the widget cannot work this out on its own and the workspace tells it. Thumbnails go through one worker rather than a thread each, and are remembered per document by path, size and modification time, so scrolling back over a card costs a dictionary lookup instead of hashing the file again. A year separator marks each change of year, and a stretch of six months or more with nothing in it collapses into a marker naming the silence, since an empty run of months is information about a correspondence rather than a gap to scroll past. When the filtered set moves between exactly two parties the cards split into two columns, one party per side, the way a chat log reads; with three or more parties it stays single sided. The layout rules (`two_party_split`, `months_between`, `timeline_marks`) are module-level functions with no widget in them, covered by `tests/test_timeline.py`.
- **A Conversations view of the workspace.** A document is a letter: one party sent it to another about a concept. Read that way the repository is a set of conversations, and this view shows them so: a list of concepts on the left, ordered by latest activity the way a messaging app orders its threads, and the open one on the right as a run of bubbles, oldest first, each the sender, the date, the purpose and the first page. What the collection's keeper sent sits on the right and what they received on the left, so an invoice and its payment read as an exchange. Who the keeper is nobody has to configure: it is the party on the most documents, sender or recipient, and when they are not in a conversation at all (a family member's letters kept in the same archive) the side is taken by whoever received most of it, since letters are kept by the one they were sent to. Most concepts are held by one document, so the list starts with those left out and a check lets them back in; on a real repository that is 199 exchanges out of 956 concepts. Clicking a bubble selects the document in the workspace, so the preview and the actions follow, double-click opens it, right-click is the same menu the list has. The list is rebuilt on an idle after the documents change and only the open conversation builds bubbles or renders pages, so the cost is one exchange, never the repository. A narrow window shows one pane at a time with a button to get the list back. The grouping and the sides are `backend/conversation.py`, plain Python with ten tests. It sits beside the timeline rather than replacing it, so the two can be compared on the same documents.
- **`MiAZFieldPills`**, the seven-field filename as a row of small colored pills, one per field, each with the field name in its tooltip and a missing field marked rather than left blank. It is read-only for now; pills that open a dropdown to edit the field want a design pass first. It is shown under the filename in the preview panel and on every timeline card, and it owns the palette both use.
- **MiAZDoctor**, a new plugin under Repository, Health: every repository health check in one pass. Documents whose name is not the seven-field convention or whose date is not a date, values used by documents that the vocabulary does not know, documents of zero length or that cannot be read, groups of byte-identical documents, values described by nothing but themselves and values nothing references any more. The verdict line counts the things found rather than the checks that found them, because "1 problem" reads as one document to fix when the one problem is 31 badly named ones. Findings are ordered worst first and each carries what to do about it; a check with nothing to say is left out, because a report should be what needs attention rather than a list of things that are fine. The checks are plain Python in `backend/doctor.py` with nine tests; the plugin gathers the data on a worker thread, since hashing a repository takes seconds, and only draws the result. On a real repository of 1326 documents it answered in 1.2 seconds: 31 badly named, 2 unknown values, 86 duplicate groups, 114 undescribed values and 18 unused ones. The vocabulary findings can be fixed without leaving the report: a value described by nothing but itself, or used by documents and unknown to the repository, gets an entry and a Save button, and a value nothing uses gets Remove. These rows began as a plugin of their own, MiAZVocabularyHealth, merged into the Doctor before release because they answered the same question from a second menu entry. The analysis is plain Python in `backend/vocabhealth.py` with eleven tests. A description counts as one when it differs from the code by more than separators, and case is a real difference: codes are upper case by convention, so "Health" for HEALTH is somebody typing a word while "GENERALI" for GENERALI is not. Comparing case-insensitively flagged 234 documents worth of HEALTH as a problem and pushed the values that really say nothing down the list.
- **MiAZRelated**, a new plugin under Documents, Search. One document is rarely the whole story: a cancellation has a request before it and a receipt after it, and they share a concept. It lists the documents belonging to the same case as the selected one, in two groups, because they answer different questions: the same parties, which is the case as one side kept it, and somebody else, which is how a request and its answer find each other. Concepts are matched the way a person reads them, so case and the underscores that stand in for spaces do not split a case in two. On the same repository it found 200 concepts held by more than one document, the largest a chain of 20. `related/chain.py` is plain Python with nine tests.
- **The Doctor report opens the documents it names.** Each finding that points at documents has a Show button; it closes the report and puts exactly those documents in the workspace, over whatever the sidebar filters say, with a chip naming the finding so the narrowing is visible and can be dropped with a click. Behind it is `DocumentQuery.only_ids` and `workspace.show_documents(ids, label)`, which any plugin can use to say "look at these"; `clear_documents()` gives the workspace back to its filters.
- **A file type badge where a page cannot be.** Only PDFs and images render a preview; a Word file, a spreadsheet, a CSV or an Outlook message left a hole where the page goes, and the hole did not say why. The grid, the timeline and the Conversations view now show the theme's icon for the file type and its extension in that place, through one shared `MiAZFileTypeBadge`. The type comes from what GIO guesses from the name, so the office, spreadsheet and text icons are used when the theme has them and a generic file icon otherwise. A PDF that cannot be rendered gets the same badge, saying PDF.
- **A Filenames view.** The fifth view button shows the filtered documents as their names on disk, one per row in a fixed width font, each of the seven fields on the colour its pill has elsewhere. It is where the keys live now that the pills say descriptions: a filter, a rename or a Doctor finding acts on `ES` and `FIN`, and this is the view that shows them side by side. It shares the document list's selection and its context menu, double click opens the document, and it carries no model while hidden. A header above the rows sorts them: one button per field in filename order, each wearing that field's colour so the header reads as a key to what is under it, then an eighth for the extension, plain like the extension on the row. Clicking a field sorts by it and clicking the active one turns it round. The header does not sort a copy: it drives the document list's own sorter, which sits upstream of the filter and the selection every view shares, so sorting here sorts Details, Grid, Timeline and Conversations too, and a column header clicked in Details moves the arrow here. Two sorters would have let one set of documents be in two orders at once. The extension is not a filename field, but the list already had a column for it, and it is how the one `.docx` in a repository of PDFs is found. `show_view('filenames')`.
- **MiAZContacts**, a new plugin under Documents, Contacts. Every document names a sender and a recipient, and until now those were codes with a one-line description and nothing else. This plugin gives each of them a record: full name, postal addresses, phones, emails, web, social profiles and bank accounts, one file per person key at `.conf/plugins/MiAZContacts/data/<KEY>.vcf`, vCard 4.0. vCard is the store, not an export format: import is a parse and a copy, export is a copy, so a card that arrives from another address book keeps the properties MiAZ does not model, and a card exported from MiAZ still opens in the address book it came from. The reader takes vCard 2.1, 3.0 and 4.0, since most cards in the wild are 3.0; the writer always writes 4.0. Bank accounts have no standard vCard property, so each one lives in its own property group, several kept apart in the same card, with holder and IBAN as the required pair: since 9 October 2025 banks in the euro area check the payee name against the IBAN before a euro credit transfer, under Verification of Payee, Regulation (EU) 2024/886, so an account on file without the exact holder is not usable for a payment. The IBAN checksum is checked and flagged on the field but never enforced, because a wrong IBAN on file beats a lost one. A new Contacts view of the workspace shows one card per distinct sender or recipient of the documents on screen, deduplicated, sent and received counted apart; it follows the filtered set the same way Grid, Timeline, Conversations and Filenames do, and holds no model while it is not the view on screen. Two additive core hooks made the view possible without disturbing what was already there: `workspace.add_view` and `remove_view` turned the fixed list of views into a registry, and `MiAZPlugin.add_workspace_view` mirrors the existing `add_workspace_page`, cleanup on unload included. The plugin category vocabulary gained Documents, Contacts. `contacts/vcard.py`, `model.py`, `iban.py`, `store.py` and `parties.py` have no GTK in them and carry the weight of testing: 29 tests for the vCard reader and writer, 39 for the model, the IBAN checksum and the party folding, 8 for the view and the editor wired to a real repository, and one more case in `tests/ui/test_ui_widgets.py` for the two view hooks, which brings that file to 36.
- **Export to directory does the copying off the main loop, and says what it did.** Exporting a few hundred documents froze the window for as long as the copy took, with nothing on screen to say why, and the toast at the end said to check the file browser whether or not a single file had been written. It now runs behind the same modal progress dialog backup and restore use, one line per document as it goes, and it ends on a count: how many of the selected documents were exported, and the first five that were not with the reason for each. The rest are in the log, and the file browser opens only when something was actually copied. The target folder, the pattern, and the two checkboxes are remembered per repository in the plugin's own config file, so a second export is one click on Apply rather than the same folder picked and the same pattern typed again. There is also an option to rename the copies: a document exported for somebody who does not know MiAZ filenames arrives as `2026-09-04 - Spain - Finance - Bank X - Invoice - mortgage - John Doe.pdf`, every field kept so two documents cannot collapse into one name, and the descriptions used for the pattern directories too. Two documents that do land on the same name get a `(2)`, rather than one silently overwriting the other. Where each copy goes is `export/layout.py` and `export/runner.py`, plain Python with no GTK in them and 31 tests; the plugin gathers the fields on the main loop and hands over tuples, since a worker thread has no business reading a model row. `tests/ui/test_ui_export2dir.py` drives the real dialog for the six things only the running application can answer.
- **MiAZHistory: undo and redo for a repository.** A new plugin under Repository, History, adding two buttons to the header bar so any change to the documents or to the configuration can be stepped back and stepped forward again. On startup it checks what the repository can offer: no history keeping tool installed shows the install command and switches itself off, a repository already tracked by something else is left alone, and a fresh repository is offered a first snapshot before anything is kept, since that costs disk space and a few minutes; none of this names the tool it depends on in the interface, only "one more program". Once ready, the plugin listens for everything that can touch the repository: documents added, renamed or deleted, the configuration vocabularies changing, and the file monitor for anything MiAZ itself did not do (a file dropped in by the file manager). All three feed one settle timer, so a burst of changes lands as a single step rather than one per file; a burst that never stops is still recorded after 30 seconds, so a long import cannot postpone it forever. A step is named after what happened, "Added 3 documents, changed settings", read from the counts the signals collected; a deletion counts every path in the one signal it fires rather than the signal itself, so removing five documents in one go reads as five, not one. A step that could not be recorded loses nothing: the file content is staged again on the next attempt regardless, and a failure merges its counts back into whatever piles up afterwards, so the next successful step is still named after everything that happened, not only the part that came after the failure. A window that settles while an earlier recording is still in flight is not dropped either: it waits and settles again once that recording finishes. The undo and redo buttons stay insensitive until there is a step to take, and their tooltip names it, "Undo: Renamed 1 document (Today at 14:32)". Clicking either opens a confirmation dialog that says when the change was made and lists the files it touched, grouped as added, renamed, changed or deleted, before anything on disk moves; a step that touched the configuration reloads the repository afterwards, so a sender removed by an undo also leaves the dropdowns that offered it. Repository Settings gains a History group reporting how many changes are kept and how much disk they use. The plugin defers to the already-tested `history` package (`distro.py`, `gitstore.py`, `summary.py`) for the actual work, and never names the tool behind it in the interface. `MiAZHistoryPlugin.settle()` is the method both the timer and the tests call.

### Changed

- **The Settings tab is a list of categories, not one long scroll.** With every plugin enabled it stacked ten groups, the repository's own two rows and then one per plugin builder, and the AI assistant's group alone holds an expander per provider. It now has a list on the left, the repository first and then one entry per category, showing two or three groups at a time. The categories are not invented for the list: the settings registry already hands its builders back sorted by the category each plugin declares, so the grouping is the one the plugin vocabulary already defines. A category nothing registers under gets no entry, since pages are added on first use rather than up front, and the repository entry survives a plugin being enabled or disabled, which the plugin entries do not: rebuilding it would throw away a half-typed repository name. The list and the stack are `MiAZSidebarStack`, shared with the Metadata tab rather than copied from it, so the two tabs cannot drift apart. Neither the plugin hook nor any plugin changed.
- **The contact cards are in alphabetical order.** They were in order of how many documents each party was named in, which is an order nobody can follow past the first screenful: looking for one person meant reading every card. They are sorted by name now, case and accents folded, so Bank X sits with BANKX and École with Ecole rather than one of them after Z. The name sorted on is the one the card shows, which is the name on the contact record when there is one and the description the documents use when there is not: sorting on the description would have put the cards in an order the names on them do not explain. Two parties shown under the same name are separated by their key, so the order does not change from one rebuild to the next.
- **A plugin declares its menu entries instead of building them.** A plugin's entries were assembled in its `startup()`: each one named its own action, wrote its own label and passed its own shortcuts, seventeen plugins doing the same thing five different ways, and five of them passed no label at all and got the plugin description as a menu item, which is why the Doctor's entry read "Run every repository health check in one pass and repair the vocabulary". The definition now says what the entries are: `MenuEntries` in `plugin_info` lists them in menu order as `(id, label, shortcuts)`, the `.plugin` file mirrors them one `MenuEntry-<id>=` key each, and `install_menu_entries({id: callback})` says only what each one does. The plugin no longer names an action, writes a label or passes a shortcut in code. Action names follow from the ids, so every entry answers to `plugin-menuitem-<Plugin>-<id>` rather than to whatever each plugin invented, and a plugin with several entries no longer has them overwrite each other under one key. Labels are unchanged on screen, MiAZProjectMgt and MiAZPeriodicity included: those two built theirs from `__config_name__` at runtime, so "Assign document(s) to projects" was a format string filled with a config key, and it is now written out as the sentence it displays. One item still cannot be declared, the scanner's submenu of whatever sources the device reports, and it asks `get_menu_entry_label('scan')` for its label so even that one reads from the definition. `MiAZPlugin.get_menu_item()` stays for a plugin written against the older API, and now warns when it falls back to the description. The plugin index reads `plugin_info` out of the source with a restricted AST evaluator rather than importing it, and that evaluator had no case for a tuple, so it learned one. `tests/test_plugin_menu_entries.py` checks the two halves of every definition agree, that ids are unique, that each declared id is wired to a callback and nothing is wired that was not declared, and that every label reached `po/`.
- **The plugin menu shows the category and the subcategory.** A plugin declares both, and only the subcategory reached the workspace menu, so the right-click menu on a selection was a flat run of Notes, Projects, Tags, Statistics, Export and Import with nothing saying what they had in common. The plugins section now holds one submenu per category, and each of those one per subcategory, so an action reads as Documents > Annotation > Create a new note. Both levels are created the first time a plugin asks for the pair and looked up by key after that, so two plugins sharing a pair land in the same submenu instead of adding a second entry with the same name; the menu rebuild that follows a plugin being loaded or unloaded already dropped both levels together, since they share a widget key prefix. The taxonomy itself was regrouped with it. Organise is gone, its four subcategories fold into Documents as Contacts, Periodicity, Projects and Search, since they all act on documents. Notes and Text become one Annotation, which is what a note and an OCR transcription both are. Repository, Statistics splits into Health for the Doctor and Stats for Insights, because checking a repository and measuring it are different errands. Interface, View splits into Behavior for column visibility and Display for fullscreen, and Fonts becomes Accessibility, which is what changing the workspace font is for. AI, Assistants moves under Documents, since the assistant reads the document in front of it. The Doctor's menu item says "Run repository health check" rather than repeating the plugin description, which is the sentence the plugin manager shows.
- The workspace filter tags are built on a new `MiAZChip` widget rather than assembling a button, a box, a label and a close icon in place. Same pill, same colors, same click to drop the filter; the code now lives in `widgets/chip.py` where anything else that needs a removable token can use it. The colors come from `MiAZFieldPills` now, so a filter tag for a sender and that sender's pill in the preview are the same color.
- The date field of the rename dialog is `MiAZDateEntry`: the typed `YYYYMMDD` entry, the label that says what the date reads as, and the calendar popover, in one widget instead of five methods and a re-entry flag spread through `rename.py`. Behavior in that dialog is unchanged. The mass rename date dialog uses the same widget and gains from it: it had a calendar and nothing else, so a date had to be clicked for, and it can now be typed.
- **The window fits a phone.** It could not be made narrower than 805px, so the `max-width: 720sp` breakpoint that rearranges MiAZ could never be reached and the adaptive code behind it had never once run. The floor is now 320px, measured, with nothing clipped. Four things were paying for it: the header bar's page switcher, the window controls, the word on the Review toggle and the four per-selection buttons. Narrow, the switcher comes off the header bar, the window controls go (a phone shell draws its own, and Quit is on Ctrl+Q and in the primary menu), Review keeps its count and loses its word, and view, rename, mass rename and delete collapse into one menu holding exactly the entries the buttons would have shown. The fifth was not in the header bar at all: an `Adw.ViewStack` is homogeneous by default, so the workspace stack asked every page how wide it wanted to be and took the largest, which let one plugin page demanding 519px set the floor for the whole window while not even being on screen. The stack now sizes to the page it is showing. Which layout is in use is a single `narrow` property on the main window, set by that one breakpoint and read by everything that has to change, so the width at which MiAZ rearranges itself is written down once. Nothing changes above the breakpoint: at 1280px the header bar is what it was.
- **The timeline card is a page beside a table.** The pills ran across the card and the page sat under them, so a card was as wide as its longest run of pills and the rule between the columns wandered from one row to the next; the page itself was small and alone in a box mostly empty. The first page now sits on the left at a fixed size, an A4 page 180px tall, and the seven fields are beside it one per row, the field name in front and the value on its pill colour: `MiAZFieldTable`, the same fields, palette and tooltips as `MiAZFieldPills` in a shape that reads down. The rows share the height of the page, so the table is as tall as the preview whatever the values say, and a document without a page shows its file type badge in the same place at the same size. The preview sits in an overlay over a fixed box, so a wide page cannot push the table, and every card has the same column. The "From X to Y" line is gone: it said what the Sent by and Sent to rows now say.
- **The export folder layout is checkboxes, not a string of letters.** Choosing how the copies are filed meant typing `CYmGP` into an entry, with a popover beside it explaining that C is the country and m is the month. The dialog now has a row of checkboxes for the date, Year, Month and Day, a row for the fields, Country, Group, Sent by, Purpose and Sent to, and an Example line at the bottom showing the exact path the first selected document will take, redrawn on every tick, including the target folder and the readable names option. Nothing ticked means one flat folder, which is what the old "Export with pattern" checkbox meant, so that checkbox is gone too. The trade is the order: folders now always nest the way the filename reads, `Year/Month/Day/Country/Group/Sent by/Purpose/Sent to`, so the old default lands in `2026/09/ES/FIN` rather than `ES/2026/09/FIN`, and an arbitrary nesting is no longer possible. The stored setting is still the letters, so a settings file written by the previous build opens with the right boxes ticked. `layout.canonical` puts the ticked letters in that fixed order and is what the checkboxes and the config file agree on; `runner.relative_target` is now the single answer to where a document goes, which is how the Example line and the copy itself cannot disagree.
- **Repository Settings has three tabs instead of six.** A plugin's settings and a repository's plugin list are both stored under `<repo>/.conf/plugins/<Name>/conf/`, so which plugins are enabled and how each one is configured are both per-repository facts, yet they were edited in three different places, only one of which was itself per-repository. An interface plugin's toggle lived in the Application Settings dialog, a window that speaks of one MiAZ installation, not one repository, so switching repositories left its row showing the previous repository's value until the dialog was reopened. A plugin with more to configure than a toggle put a Configure button in the Plugins tab that opened a dialog of its own, a second window on top of the first for something that belonged in it. A plugin with neither had no home for its settings at all. All three collapse into the Repository Settings dialog's own Settings tab: `install_settings_group(builder)` lets a plugin offer an `Adw.PreferencesGroup`, built only when the tab is actually shown so a slow builder, such as AutoScan asking SANE what devices exist, is not paid for just to open the dialog. The Metadata tab gained a second hook for a different problem: MiAZPeriodicity and MiAZProjectMgt do not own a preference, they own a repository vocabulary, the periodicities and the projects, and each still opened its own manager dialog from a menu entry, putting a vocabulary two dialogs deep. `install_metadata_view(name, title, icon_name, factory)` lets a plugin add its vocabulary to the same list as Country, Group, Purpose, Sent by and Sent to, so periodicities and projects now sit beside them rather than behind a button. Both plugins' `manage` menu entry opens Repository Settings on that page directly, and the method behind it is named `show_manager` rather than `show_settings`, since it opens a vocabulary manager, not a settings dialog. Repository Settings itself is left with the three tabs this leaves it: Metadata, Plugins and Settings.
- Development opens on 0.3.0.

### Fixed

- **`miaz search --from` and `--to` never worked.** Any use of either flag ended in a traceback and exit code 1: `TypeError: '<=' not supported between instances of 'datetime.datetime' and 'datetime.date'`. Two defects sat on the same comparison. `_parse_date` in the console returned a `datetime` while `parse_date` in the query model returns a `date`, and Python refuses to compare the two, so even a range with both ends set crashed. On top of that, giving only one of the two flags left the other bound `None`, which does not compare against anything either. `_parse_date` now returns a `date`, and `_matches_date` treats an unset bound as no limit on that side, so `--from` alone means everything since that date and `--to` alone everything up to it. A range whose `--from` is later than its `--to` is now a usage error on stderr with exit code 2, rather than a silent empty result. `--since` was never affected, because `resolve_preset` already returned dates.

  The reason the suite was green is worth recording: `test_explicit_range` asserted only that the query object had been built with two non-`None` bounds. Nothing in the console tests ever ran a built query against a document, so the entire flag pair could be dead without a single test noticing. The new tests filter real documents, and one of them pins the bound type directly, next to the equivalent check the preset path has had since 0.3.

- **The UI test suite left three documents in the shared repository.** Every repository in the UI suite is built once per session, so a document written by one test file is still there when the next one counts what the workspace displays. `tests/ui/test_ui_history.py` added three documents dated December 2026 and never removed them, which broke twelve tests in four other files: the document counts in `test_ui_repository`, `test_ui_workspace` and `test_ui_widgets`, the `future` date preset in `test_ui_sidebar`, and the conversation view ordering in `test_ui_widgets`, where the leaked documents sorted ahead of the fixtures the test expected. The module now snapshots the repository before it runs and removes anything it added afterwards, recording the removal so the git store is not left with uncommitted deletions. The sweep runs once at the end rather than between tests, because these tests build on the history they record between them.

- **`miaz search --limit` accepted counts that are not counts.** `--limit -1` sliced `items[:-1]`, which quietly dropped the newest document and looked like a search returning the wrong answer rather than a flag being wrong. `--limit 0` was ignored and left the "documents need review" hint reading as if the search had genuinely found nothing. Both are now a usage error on stderr with exit code 2, checked next to the other flag conflicts so a repository that cannot be opened is still reported first.

- **The console can now ask for the documents a field was never filled in for.** `_matches_value` has always understood two sentinels, `Any` and `None`, but `build_query` upper-cased every `--field` argument before handing it over, and `'ANY'` is not `'Any'`: both sentinels turned into ordinary codes that match no document. `--country none` now finds the documents whose country is blank, and `--country any` means what leaving the flag out has always meant. An ordinary code is still upper-cased, so `--country es` and `--country ES` are the same search. The one cost is that a real code spelled ANY or NONE cannot be searched for; no vocabulary in this project uses either.

  This matters more than a missing sentinel sounds. `filename_normalize` gives anything dropped into the repository under a name MiAZ did not write seven fields with only the concept filled in, so "the field is empty" describes every document waiting to be filed. On a 1322 document repository that is 29 with no country and 31 with no recipient, and until now the only way to see them was to read the review list one document at a time.

- **The Settings tab listed "Repository" twice.** One entry was the repository's own page, holding its name and location. The other was the plugin category MiAZDoctor and MiAZHistory file themselves under, which `_page_for` gave a page of its own. Both were titled "Repository", one directly under the other, and nothing in the list said which held what. A setting about the repository now goes on the page about the repository: the category folds into the page that is already there, so the list shows one Repository entry, still first. The heading over the name and location rows is gone with it, since the page is already called Repository and repeating it over the first two rows read as a narrower thing than it was.

  The repository page is deliberately never rebuilt, so the groups plugins add to it are now tracked and taken off before a plugin change rebuilds them; without that each one would appear twice. A test covers that rebuild, and another asserts no two entries in the list carry the same label, which is the fault as the user met it.

- **The plugin handler census was blind to two of the six plugins it was meant to prove itself against.** `test_the_census_sees_a_plugin_connecting` exists to show the leak detector can see a plugin take hold of something, and it failed for MiAZColumnVisibility and MiAZFullscreen because the census watched only six application objects. Neither plugin touches them: MiAZFullscreen follows the window's `notify::fullscreened` and takes F11 from the window key controller, and MiAZColumnVisibility connects no signal at all, it adds a `GestureClick` controller to the column view. Both connect to `workspace-loaded` only when the workspace is still loading, which in the harness it never is. The census now watches the window and its key controller, and counts the event controllers on the window and the column view, because a controller left behind is the same bug as a handler left behind and just as invisible. `count_handlers` also matches on the signal detail when there is one, so `notify::fullscreened` counts the one handler that matters rather than all 24 notify handlers on the window.

  This widened the leak test as much as the proof test. Deleting the `remove_controller` from MiAZColumnVisibility and the `disconnect` from MiAZFullscreen now fails `test_a_plugin_disconnects_everything_it_connected` for both; before, either leak passed unnoticed.

- **Four repository-switch UI tests counted documents against whatever date filter the day produced.** The workspace opens on the nearest date preset that is not empty, walking outwards from "this month" so a repository whose documents are all old does not appear blank. The sandbox documents carry fixed dates, so which preset that walk stops at moves with the calendar: on 9 September 2026 it stopped at "since last 3 months", which holds one of Alpha's three documents, and `test_switching_reloads_the_documents` failed its opening `== 3`. The neighbouring test asserting the same count passed only by accident, because its detour through Beta widened the preset to "since two years ago" on the way. All four counts now run under `clean_view`, which selects "all documents" first, as the workspace and sidebar files already did. The application behaved correctly throughout; the tests were reading a filter and calling it a repository.

- **MiAZHistory: both paths that refuse a repository crashed instead of refusing it.** The plugin has two ways to say it cannot work here: no history keeping tool installed, and a repository already tracked by something else. Both assigned the result of `srvdlg.show_error` and called `present()` on it. `show_error` presents the dialog itself and returns nothing, so both raised `AttributeError` before `disable_self()` could run. The exception left `prepare()` through `do_activate`, so the plugin failed to load, MiAZ put up a plugin load failure banner, and because the plugin was never removed from `plugins-used.json` the whole thing happened again on the next launch, and every launch after that. Every user without the tool installed, and every user who already versions their documents themselves, hit one of the two. Both now call `show_error` as a statement with the window as `parent`, and switch the plugin off as they were meant to. Four tests cover the pair, and they are the first tests of that region at all.

- **MiAZHistory: undo and redo no longer throw away work that was never recorded.** A step writes the whole working tree, so anything on disk that had not reached a state was overwritten with nothing to go back to. The dangerous cases were not exotic: a recording that fails leaves the tree dirty and deliberately does not re-arm, so the undo button stays lit over an unrecorded change indefinitely; a plugin's own settings file is written with no signal for the settle timer to hear; and a document replaced inside the 1.2 second settle window is unrecorded by definition. In each case one click on Undo destroyed the newer content, in no commit and unrecoverable. A step now commits whatever is uncommitted before it moves anything, as its own state named "Changed outside MiAZ", the same name catch_up uses for work MiAZ did not do itself. The rescued state is appended as the newest one and nothing ahead of it is dropped: `record()` drops what is ahead because a change made after stepping back is the user starting a new branch of their work, and this is not that, it is work that was already there and was only never written down. So the step does what its dialog promised, and the rescued work comes back by stepping forward.

- **MiAZHistory: a step and a recording could run against the working tree at once.** `settle()` commits on a worker thread and `apply_step` only checked whether another step was running, so a click on Undo landing during a recording put two git processes on one repository. They fight over `.git/index.lock`, and if the step landed between staging and committing, the recording committed the stepped-back tree as a state the user never made, leaving the timeline describing something that was never on disk. `apply_step` now refuses while a recording is in flight, both buttons go insensitive for the duration of a recording so the click cannot be made in the first place, and `GitStore` takes a reentrant lock in every method that writes, so nothing outside the plugin can produce the same overlap either.

- **MiAZHistory: an interrupted first snapshot no longer locks the plugin out of the repository for good.** `init()` created the repository, then took the baseline snapshot, which is minutes of work on a large one, and only then wrote the state file that marks the history as MiAZ's own. Quitting or crashing in between left a repository with no state file, which reads as somebody else's, so every later activation refused it and said so, and the only way out was deleting a directory the interface may not name. The state file is now written as soon as the repository is created, with an empty timeline, and the next run picks the documents up as its first recorded change.

- **MiAZHistory: a half-written index file no longer takes the whole history with it.** Both JSON files the plugin writes were written straight over the top, so a crash or a full disk mid-write left something that would not parse. Reading the state file back swallowed that failure and returned the same empty timeline it returns for a repository with no history at all, which looks healthy: both buttons grey, nothing wrong on screen, and the next recorded change writing over the top of every state the user still had. `plugins-used.json` was worse, because it is written from a worker thread while the main thread may be reading it and `MiAZConfig.load` turns a parse error into an empty configuration, which opens the repository with every plugin apparently switched off. Both are now written to a temporary file, flushed to the disk and renamed over the target, so a reader sees either the old file or the new one. A state file that will not parse is now reported rather than read as empty: the plugin says the change could not be recorded instead of quietly dropping the history.

- **MiAZHistory: a repository that stops answering no longer hangs the plugin silently.** No git command carried a timeout, so one blocked on a lock over a network share, which the design explicitly allows, waited forever. The flags that guard a recording or a step stayed set, both buttons stayed dead, and the plugin stopped recording with no toast and no line in the log. Every command now has one: two minutes for a command that answers a question, an hour for one that writes the whole tree, since a first snapshot of several gigabytes is legitimately slow. A timeout is reported the same way any other git failure is.

- **MiAZHistory: the undo and redo buttons left their keys behind when the plugin unloaded.** They were registered with `app.add_widget` directly rather than through the plugin, which is what arranges for a key to be dropped on unload. After a deactivate or a repository switch, `headerbar-button-history-undo` and its twin resolved to detached buttons. `MiAZPlugin` gains `register_widget(key, widget)` for exactly this case, a widget the plugin keeps its own reference to but does not attach itself, such as the buttons inside a box that was attached as one.

- **MiAZHistory: a filename that looks like markup no longer breaks the confirmation dialog.** The dialog body renders as Pango markup, and an unescaped `&` or `<` in a document name makes it unparseable, which is easy to get from a file dropped in by the file manager and recorded as changed outside MiAZ. The user was then asked to confirm a step that rewrites their documents against a body that was empty or broken. The body is escaped before it reaches the dialog.

- **A repository backup no longer archives the history along with the documents.** `util.zip` went through `shutil.make_archive`, which takes no exclusion and archives dot entries, so once MiAZHistory was keeping a copy of every document under `.git`, a repository backup roughly doubled in size and in time to store a second copy of what the archive already held. `util.zip` gained an `exclude` argument that skips an entry by name at any depth, and `backup_repository` passes `.git`. Backing up the configuration was never affected, and neither was the plain file backup, which already skipped hidden entries. A restore therefore brings back the documents and the configuration but not the undo history, and the plugin offers to start a new one.

- **The Doctor's list of copies says which document is a copy of which.** Show on "Groups of documents with identical content" put 177 documents on screen in date order, and nothing on that screen linked them: 86 groups, indistinguishable from a list of 177 unrelated documents. Everything needed was already there and switched off. The Details view has a Copy column that marks a document whose bytes match another one and names its twins in the tooltip, with a sorter whose key is the first name in the group, so a group comes out contiguous and a document with no twin sorts last. The column is revealed by the duplicate scan, and the scan only ran on entering Review. `workspace.show_duplicates()` now asks for both: it scans when the map is stale, on a worker as before, and puts the view in copy order when the scan lands, since the sorter reads the map and would otherwise order the rows against an empty one. MiAZDoctor calls it for the duplicates finding and for no other, because the rest are not about content and should not pay 0.9 seconds of reading for a column that would stay empty.

- **A person's description is one description, in every file that holds it.** A person lives in four configuration files: `people-available.json`, the pool of everybody the repository knows, and three used lists, `people-used.json`, `senders-used.json` and `recipients-used.json`. Every place that wrote a description wrote one of them, so the same person could be ADAC in the sender list and ADAC e.V. in the pool, and the Doctor went on reporting a value it had just been told the name of. Two paths were broken in different ways. The repository manager's Edit wrote its own configuration's pair and showed a toast saying the item had been "renamed globally", which it had not: editing a sender left people-used untouched, and the same person in the recipient list kept the old text. The Doctor's inline form wrote nothing at all: it saved through `add_used`, which adds a key and leaves a key that is already there alone, and every value the check offers that form for is already there, described by nothing but itself. Both now go through `config.set_description(key, description)`, which writes the description into every file of the repository that holds the key, across the configurations that share a vocabulary. It writes a description, never a membership: a key absent from a list stays absent, so naming a person nothing was ever sent to does not turn them into a recipient. Adding is still `add_available` and `add_used`, and the Doctor's form does both when the value is genuinely new, which is the case its other half is for, a value used by documents and unknown to the repository. `MiAZConfigStore` gives each configuration a back-reference to itself so a config can reach the ones sharing its vocabulary, declared as `shared_with` on the three people classes and empty everywhere else.

- **A Doctor "Show" showed nothing whenever the sidebar was narrowed.** The report's Show button installed the list of documents a finding named and left every other filter in place, so what landed on screen was the intersection: text in the search box, or a field narrowed to a value those documents do not use, hid part of the list or all of it. Review hid all of it every time, whatever the finding, which is the state this was reported from: Review asks for documents pending review, an explicit list lifts the pending check because the documents a health check names are usually the ones the ordinary view hides, and a query that asks for pending documents while treating every document as reviewed matches nothing at all. `show_documents` now clears the search entries, the field dropdowns, the plugin dropdowns and the Review toggle before it installs the list, so the list is what it says it is. The date range is left alone: an explicit list ignores it anyway, and leaving it means dropping the list gives back the range the user had rather than the first preset, which is usually empty. The same applies to the Contacts card's "documents of this person", which goes through the same call. Alongside it, `show_pending_documents` no longer runs while the filter controls are being written programmatically: it cleared the filters, which undid whatever the caller was in the middle of writing, and that made it impossible to set the whole filter state in one go.

- **Opening the Settings tab took four seconds.** Measured per builder: MiAZAutoScan's was 3969ms of 4304ms. Its settings group called `_list_devices()`, which runs `scanimage -L` and wakes the scanner, on the main loop. The plugin already probes the device once at startup on a worker thread to build its menu, with a comment saying why it is backgrounded, and then threw the answer away; the settings group asked again, synchronously. It now reads what that probe found, and tells the two states apart that used to look alike: a probe that has not answered yet says so, and one that answered and found nothing offers the manual device entry as before. MiAZImportFromScan was the next largest at 223ms, walking every .desktop file on the system to list the scanner applications. Activation already walks them to decide whether the plugin has anything to offer, stopping at the first match, so that walk now collects them all and keeps them, and the settings group reads the list rather than repeating the walk. Together, 4304ms to 133ms. The lazy build this replaces was not wrong, it deferred the cost to the moment the tab is opened, which is exactly where it was then felt.
- **A long concept no longer drags the timeline card out of line.** The headline wrapped, and a wrapping label asks for its whole text on one line as its natural width and for its longest word as its minimum. Everything else in the card asks for a fixed width, the preview being a fixed box and the field pills capping at 30 characters, so the headline was the one part that could ask for more: a document called HOURLY LEAVE RATE CORRECTION RETROACTIVE RECALCULATION PAYSLIPS JAN AUG 2025 made its card half as wide again as the one under it, 728px against 476px, and since each row centres its own rule between its two halves, the rule stepped sideways at every such row. The headline is cut with an ellipsis now, capped at 40 characters, which keeps its request under the rest of the card with room to spare, and the whole concept is in the tooltip. What the test checks is the width rather than the setting: three concepts of very different lengths must produce the same card, so the cap can be revisited, or the pills and the preview resized, without the alignment quietly going again.
- **The workspace toolbar carries what acts on the documents.** Views on the left, then Add, the preview toggle and the per-selection buttons (view, rename, mass rename, delete) in the middle, where plugins put theirs too, then what belongs to the view being shown on the right. Those buttons were in the header bar, a corner of the window away from the list they act on, and they were most of what stopped the window fitting a narrow screen. The header bar keeps the Review toggle, the sidebar toggle, the title and the primary menu. Six pixels sit between the toolbar and the documents.

## [0.2.0] - 2026-08-31

### Changed

- **The plugin section of the workspace menu is one level shallower.** MiAZProjectMgt and MiAZPeriodicity each hung a submenu named after the plugin inside the entry already named after the plugin, so reaching Assign meant Projects, then Project, then Assign, and setting a periodicity meant Tags, then Periodicity, then Set. Both now append their three actions straight into their own entry. MiAZNotes' Backup and Restore sat in two top-level entries of their own holding one item each, away from the Notes entry; they act on the notes, so that is where they are now.
- MiAZNotes' `Notes…` entry is `Create a new note` and opens on a blank note rather than on the list. It also works on a selection of more than one document: the note is written once per document when it is saved, the same text filed against each of them. It used to return silently unless exactly one row was selected, which looked like a dead menu entry with no way to tell why. `All Notes…` is `See all notes…`, since it opens a view rather than asking anything. `Ctrl+N` is unchanged.
- `tests/ui/test_ui_plugin_menus.py` asserts the shape of that menu: what the Notes entry holds, that Backup and Restore are not entries of their own, that Projects and Tags hold their actions directly, that no entry nests a submenu of its own name, and that one note reaches every selected document.

- **Plugin categories are six words instead of fifteen phrases.** The vocabulary was 15 categories and about 50 subcategories, most of them describing an enterprise document system nobody was going to write a plugin for (`ETL and Data Processing`, `Archiving and Compliance`, `Real-time Collaboration`), and the names were longer than the actions they held: reaching "Toggle fullscreen" meant `Customisation and Personalisation` then `User Interface`. It is now `Documents` (Import, Export, Text, Notes, Convert), `Organise` (Tags, Projects, Search), `Repository` (Backup, Restore, Statistics, Sync), `Interface` (View, Fonts, Themes), `AI` (Assistants, Models) and `Help` (Examples, Diagnostics). Every name is one word, because the subcategory is the label of a workspace submenu.
- Three plugins were filed wrongly. `MiAZOCR` sat under `Artificial Intelligence / Document AI`, which told the user something false: it shells out to `ocrmypdf` and `tesseract`, with no model and no provider anywhere, so it is `Documents / Text` now. Keeping it out of `AI` is what makes `AI` worth having as a category: it marks the plugins that send document content to an external service. `MiAZNotes` was under `Collaboration / Comments and Annotations` in a single-user desktop application, and is now `Documents / Notes`. `MiAZInsights` was under `Analytics and Reporting / Custom Reports` while publishing a fixed dashboard, and is now `Repository / Statistics`.
- The category pair is checked when a plugin registers. Nothing validated it before, and three plugins had drifted onto `User Interface`, a subcategory the vocabulary never defined; they kept a translated menu label only because `settings.py` happens to contain the same literal for an unrelated preferences group. `MiAZPlugin.register()` now logs a warning naming the unknown category or subcategory, and `install_menu_entry(category=..., subcategory=...)` does the same for the pair a plugin names to file an action somewhere else.
- `plugin_categories` marks its names with a local `N_()` rather than `_()`. No code reads that dict, but it is not decoration: its calls are what `xgettext` extracts, and both display sites translate the value they read at runtime, `_(category)` in `configview.py` and `_(subcategory)` in `app.install_plugin_menu`. Under `_()` the keys were translated at import, so they could never be compared against a `.plugin` file, which is always English. `N_()` keeps the key English and still puts the name in `po/`. The Notes backup and restore entries were passing `_('Data Management')` into `install_menu_entry`, which then looked the already-translated string up a second time; they now pass `Repository` and `Backup`/`Restore` in English. The catalogue lost 106 msgids in the trade and the 25 new names are translated into Spanish.
- `tests/test_plugin_categories.py` covers what nothing covered: every bundled plugin declares a pair the vocabulary defines, the `.plugin` file and `plugin_info` agree (the pair is written twice), every name is one word, and every name reaches `po/es_ES.po`.

- **Adding documents from a directory** and **Copy document names** are core, not plugins. Both were `MiAZAddFromDir` and `MiAZCopy2Clipboard`, enabled per repository, which meant a repository could be set up unable to do either. Neither is optional work: one is how a folder of scans reaches a new repository, the other is how you get a list of what you selected out of the app. `MiAZAddFromDir` was also in the default set written into every new repository, so it was a plugin in name and a core feature in practice. On a large repository a substantial share of the review queue turned out to be copies of documents already filed, clearable on sight. The tooltip names the twin and says whether it is filed already, because which copy to discard depends on that. The outcome was a toast, which is three seconds of a message about an operation that just replaced every document the user has. The work now goes to a worker thread through a new `progress` service (`frontend/desktop/services/progress.py`): `run(work, title, on_close=...)` makes the window content insensitive and presents a modal dialog that names the file being copied and fills a bar, refuses to start a second operation while one is running, and cannot be dismissed until the work ends. Then it says what happened, in a message that stays until it is read, and the UI comes back when the user closes it. A restore restarts MiAZ on that close, not the moment the last file lands. The dialog disables the window *content*, never the window: libadwaita hosts dialogs beside the content rather than inside it, so disabling the window would take the dialog's own Close button with it. Close is enabled before the outcome is worded, so work that returns something unexpected cannot leave the application locked behind a dialog that will not close. `MiAZDR` and MiAZNotes' `NotesBackup` take an optional `progress(message, fraction)` callback, reported per file where there is a file count and per stage where there is not: `shutil.make_archive` and `zipfile` say nothing while they work, so the bar pulses rather than inventing a percentage. Covered by `tests/ui/test_ui_progress.py` (the UI is held, a failure is reported, a second operation is refused, and an outcome that cannot be worded still closes) and five backend tests in `tests/test_dr.py`.

### Added

The gate read `Gtk.MAJOR_VERSION >= 4 and Gtk.MINOR_VERSION >= 6`, which is not a version comparison: it calls GTK 5.0 too old, and the Adw line written the same way called libadwaita 1.5 new enough. Both floors were also simply wrong. The code calls `Gtk.FileDialog` and `Gtk.FontDialog` (4.10) and `Adw.InlineViewSwitcher` (1.7) and `Adw.ShortcutsDialog` (1.8), none of them guarded, so the declared GTK 4.6 and Adw 1.6 were below what MiAZ actually needs. Nothing about the requirement changed here: `Adw.InlineViewSwitcher` landed on 15 May 2026 and `Adw.ShortcutsDialog` on 7 July, both before 0.1.50 and 0.1.60 shipped, so those two releases already needed 1.8 while declaring 1.6. `GTK_MINIMUM` and `ADW_MINIMUM` are now `(4, 10)` and `(1, 7)`, compared as tuples, and the refusal names the version found next to the version needed instead of quoting numbers that were not the requirement. `tests/test_toolkit_version.py` derives both floors from the GIR files and fails if either drops below an API the source calls, so the two numbers cannot drift from the code again. README and AGENTS.md said 1.6 as well.
- CI was running MiAZ on a libadwaita it cannot start on, and reporting it as a test failure. `ubuntu-latest` still pins to Ubuntu noble, the previous LTS, which ships libadwaita 1.5, so the version gate exited before pytest collected anything and all 40 UI tests errored at setup with `SystemExit: -1`. Current Ubuntu is not affected: 26.04 ships 1.9.1 and 25.10 ships 1.8. The job now runs in a `fedora:43` container (GTK 4.20.4, Adw 1.8.7) and prints both versions before it runs anything, so the next floor problem reads as a floor problem. On the runner: ruff, 606 unit tests, 112 UI tests and both validators, in about nine minutes.
- The UI tests no longer die on the runner the moment they build the application. Constructing the app builds the workspace, which builds `MiAZBrowserPage`, which builds a `WebKit.WebView`, and WebKit isolates every view with bubblewrap, which has to create a user namespace. GitHub's container does not allow that, so the first test that made an application took a `SIGTRAP` six seconds in; rootless podman does allow it, which is why the same image passed here throughout. The UI step sets `WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS=1`, which is safe in that one place and nowhere else: the pages are local files this repository produced and the container is destroyed with the job. Finding it needed `PYTHONUNBUFFERED=1`, which stays: Python buffers 8 KiB when its output is a pipe, so a process killed mid-run loses everything it wrote, and a six second step had left no output at all to read.

The Meson job hung inside `apt-get` on 19 August and ran for six hours before GitHub killed it at the ceiling, because `timeout-minutes` was set on neither job. Both have one now, 30 and 20 minutes against real runtimes of about seven and three, and the apt job sets `DEBIAN_FRONTEND=noninteractive` so a package that stops to ask a question fails instead of waiting for an answer nobody will give.
- The duplicate-scan test suite passes on CI. `test_an_unreadable_file_is_skipped` made a file unreadable with `chmod 0o000` and expected the scan to skip it, but the runner's container runs as root, and root reads a `0o000` file regardless of its bits. - MiAZ no longer segfaults while the duplicate scan finishes. `scan_duplicates` runs in a worker, and it emitted `duplicates-scanned` from that worker, so the workspace's handler (`column.set_visible()` and a refilter of the column view) ran on the worker thread. The core dump caught both threads inside `gtk_list_item_manager_model_items_changed_cb` on the same list: the worker was freeing `GtkColumnViewRowWidget`s while the main thread walked the rb tree those nodes live in. GTK may only be touched from the main loop, so the index now delivers `duplicates-scanned` and `index-loaded` through `GLib.idle_add` when it is not on the main thread, and inline when it is, which keeps the console (no main loop to drain the idle queue) working. `tests/test_index.py` runs a scan in a worker and fails unless the handler lands on the main thread.

The crash handler already in place only ever saw Python exceptions, and a crash inside GTK is not one: the log simply stopped mid-line and the only evidence was a core dump full of C frames. Over SSH without X forwarding, in a container or on a headless server, GTK imports fine and has nowhere to draw. `Adw.Application` does not refuse to start there: it runs `startup`, emits `activate`, and dies building the first widget with `RuntimeError: Gtk couldn't be initialized`, by which time the plugin index is built and the web server is listening on a port. ## [0.1.60] - 2026-08-19

### Added

- A command line that runs without a display: `miaz search` finds documents in any repository and `miaz repos` lists the repositories it can search. Results are one filename per line so they pipe into `xargs` and `grep`, `--long` prints a table with the expanded labels, and `--json` prints flat records (`jq -r '.[].concept'` works without digging). Filters map one to one onto `DocumentQuery`, the same object the workspace filter uses, so the two cannot drift apart: the command line contains no search logic of its own, and a test asserts that a query built from flags equals one built by hand. Exit codes are 0 results, 1 no results (so `if miaz search x; then` behaves like `grep`), 2 wrong arguments, 3 repository problem. An empty result on a repository whose documents all fail validation says so on stderr instead of printing nothing, since the workspace hides those documents too. Bare `miaz` still opens the window, and `--version` is unchanged.
- `--repo NAME_OR_PATH` searches a repository other than the current one, by registered name or by path, without rewriting the default. That needed `MiAZRepository.use(repo_id=None, path=None)`: `repository.get()` always resolved the `current` repository, so the only way to read another one was to write `current` first, which changes what the desktop app opens next time. `miaz repos` exists so the names are discoverable.
- 34 UI tests in `tests/ui/`, run by `scripts/checks/run_ui_tests.sh` and by CI under `xvfb-run`. They start the real application against a throwaway repository and assert on real widgets: what the workspace displays, the sidebar dropdowns, the rename dialog, the plugin enable and disable cycles, and repository switching. No synthetic input and no screenshots; the main context is iterated by hand rather than running `app.run()`, which is what makes the application drivable from a test. `HOME` points at a temporary directory for the duration, so they never touch a real configuration, and a plain `pytest` run skips them. `tests/manual/UI-CHECKLIST.md` is the companion for what a machine cannot judge, and marks the 29 items the suite covers.
- New `MiAZConsoleApp` (`MiAZ/frontend/console/app.py`) gives the backend the six things it asks of an application object and registers three services, `util`, `repo` and `index`, with no GTK anywhere. A third rule in `tests/test_boundaries.py` fails if anything under `frontend/console/` imports Gtk, Adw, Gdk, Pango, GdkPixbuf, WebKit or `MiAZ.frontend.desktop`, and it counts the files it checked so a wrong path cannot make it pass vacuously.

### Changed

- Switching repository no longer restarts the application. Settings > Repositories still asks before switching, and the dialog now carries a **Set as the default repository** checkbox: the switch and the choice of what MiAZ opens next time are two separate decisions, so a repository can be looked at without becoming the default. The Settings dialog stays open and a toast names the repository switched to. What the restart was really covering was the plugins: `app.load_plugins()` refused to run twice, so the second repository kept the first one's plugins and ignored its own `plugins-used.json`. `MiAZWorkflow.switch_start(repo_id=None)` now unloads them first (new `pluginsystem.unload_all()`, the same teardown a manual disable runs) and loads what the new repository enables. `MiAZRepository.get_active_id()` says which repository is on screen, which is not `App.current` after a switch that did not set the default; the window title, the sidebar, the settings title and `MiAZInsights` read it instead. Covered by 10 new UI tests (`tests/ui/test_ui_settings_repo.py`, plus the plugin and non-default switches in `tests/ui/test_ui_repository.py`, whose two sandbox repositories now enable different plugins) and 6 in `tests/test_repository.py`.
- Every logger lives in one hierarchy under `MiAZ`, so the standard library works on them: `logging.getLogger('MiAZ.Index')` returns the logger MiAZ uses, `setLevel` on a parent controls its whole subtree, and `dictConfig` has a way in. `MiAZLog` was a `Logger` subclass constructed directly, which kept its instances out of the logging manager entirely and gave each one its own console handler. It is now a factory over `getLogger` with the same name and the same 66 call sites; names are normalised into the tree (`MiAZPlugin` becomes `MiAZ.Plugin`, `Plugin.MiAZInsights` becomes `MiAZ.Plugin.MiAZInsights`). The console handler and the file handler sit on the `MiAZ` root and children reach them by propagation, so a running app has 69 loggers sharing 2 handlers where it once had 101 loggers with 202. The root does not propagate further, so MiAZ output is never duplicated into a host application's root logger. `log.py` drops from 224 lines to 184.
- `MiAZLog('name')` returns the same logger every time instead of building a new one per call. A running app held 101 loggers under 66 names with 202 console handlers, 19 of them for `MiAZPlugin` alone, all printing that same name: the duplication bought nothing and cost a handler each. The registry is now keyed by name with weak values, and the instance is configured and published under a lock so a worker thread never sees a half-built logger. Same app afterwards: 66 loggers, no duplicates, 132 handlers.
- The console shows INFO and above; DEBUG goes to the log file only. Every run writes a fresh `~/.MiAZ/var/log/MiAZ.log` and keeps the run before it as `MiAZ.last.log`, so the file from the session that just failed is still there after a restart. `MIAZ_DEBUG=1` puts DEBUG back on the console. Rotation still caps a single runaway run.
- Log output is coloured only when it is going to a terminal, and honours `NO_COLOR`. Escape codes used to be written whatever the stream was, so `miaz search 2> log.txt` filled the file with them. A message logged at a non-standard level is no longer lost either: the formatter looked its colour up in a dict of the five standard levels, so a plugin calling `log.log(25, ...)` raised `KeyError` inside the formatter, and logging dropped the message and printed its own error instead. `MiAZLog.add_file_handler`, `enable_file_output`, `disable_file_output` and `has_file_handler` are gone, having had no callers since `enable_file_logging` replaced them. New `tests/test_log.py` covers all of it; the module had no tests.
- Log lines go to stderr instead of stdout. Diagnostics have no business on the stream that carries results: with them on stdout, `miaz search --json | jq` could never have worked. New `log.set_console_level()` raises the console level of every logger, existing and future, which the command line uses so it prints results rather than a startup narration. `MIAZ_DEBUG=1` brings the usual output back. Nothing parses MiAZ's stdout, so the desktop app is unaffected.
- What a date preset means now lives in `MiAZ/backend/query.py` (`resolve_preset`) rather than inside the workspace loop that builds the sidebar entries, so the sidebar and the command line resolve `last-6-months` through the same function. The workspace keeps the labels, which are its business. The Future entry no longer hardcodes its `99991231` upper bound either. A test walks `DATE_PRESETS` and fails if a token has no meaning.
- `MiAZRepository.load()` no longer clears the configuration cache on entry. Invalidating is the caller's job (`reset()`, which both callers already call before validating), and clearing it there discarded a repository chosen with `use()`: the next lookup resolved `current` again and loaded a different one.

### Fixed

- Quitting no longer leaves a WebKit warning behind. Each WebKit view runs in its own subprocess holding a D-Bus name, and quitting without stopping them closed the bus connection first, so the child complained on the way out with `Error releasing name ...WebProcess-<uuid>: The connection is closed`. Every view under every window is now stopped before the main loop ends. `try_close()` alone is not enough: it asks the page to close and returns immediately, so the process is still running when the loop stops; `terminate_web_process()` is what actually ends it. The warning is printed by the child process, so the parent can never catch it, only avoid causing it.
- `Gtk.Calendar.select_day()` is deprecated since GTK 4.10 and warned on every keystroke in the rename date field, since validating a date moves the calendar. Both callers use the current setters through one `calendar_select_date()` helper, which also isolates the trap that `set_month()` counts from 0 while every other date API here counts from 1.
- Three raster icons sat in the `scalable` icon directory, which is what both the deb and the rpm policy checks complained about. `res-projects.png` was referenced nowhere and is gone; the other two moved to `48x48/apps`, where a 48-pixel PNG belongs, with that directory added to the icon search path.
- The plugin directories are no longer scanned twice at startup, nor again on every repository switch. `create_plugin_index` did two unrelated jobs in one call: scan both plugin directories and parse each module with `ast`, then write the result into the open repository's available set. The plugin system ran it in its constructor, before any repository exists, so the second half failed with `Skip. Plugin config not ready yet` and the scan was thrown away; the repository switch that followed a moment later ran the whole thing again. What is on disk does not depend on which repository is open, so the two are now `scan_plugin_index` and `update_available_plugins`: the scan runs once at startup and again only when a plugin is really added or removed, and a switch writes the available set without rescanning anything. The warning is gone with the wasted work that caused it.
- The Browser page stopped reloading itself once per plugin. It refreshes on `plugins-updated`, which the loader emits per plugin rather than per load, so a repository with 18 plugins scanned the WWW directory 18 times and issued 18 `load_uri` calls for the same URL in a third of a second. The refresh is now debounced, and it only reloads the view when the page it would show actually changed, which also stops a plugin being enabled from throwing away the scroll position of an unrelated page. A change to the page content on disk still forces the reload, which is what that path is for.
- A remote repository was polled twice as often as intended, and one of the two pollers could never be stopped. `MiAZWatcher.__init__` calls `set_path()`, which arms the poll, and then armed a second one itself, overwriting `_timeout_id` with the new source id. The first source kept running with its id lost, so neither `set_path`, `set_active` nor a repository switch could remove it, and every watcher built leaked one. The interval is now a single `REMOTE_POLL_SECONDS` constant instead of two separate literals that could drift apart.
- The archive check added for plugin imports now covers every extraction. `pluginsystem.install_plugin` called `zipfile.extractall` directly and `MiAZNotes` restore called `zipfile.extract`, so two of the three paths that unpack a user-supplied archive skipped it, including the second half of the same plugin-install feature. The check is now the module-level `util.check_zip_members`, reachable without the app object, and all three go through it. `util.unzip` also closes the archive when it refuses, and `install_plugin` no longer leaves a `ZipFile` open when the plugin fails validation. To be clear about what this is: CPython's `zipfile` already strips `..` and leading separators, so nothing was escaping; the check refuses out loud rather than silently relocating a member, and it is the guard that has to exist if extraction ever moves to `tarfile`.
- MiAZ reads the date out of the document name instead of suggesting today. `util.filename_guess_date` recognised exactly one shape, an eight-character token between underscores that parses as `%Y%m%d`, and fell back to the file mtime for everything else. Since `filename_normalize` keeps the original filename in the concept field, `Factura 15-03-2024.pdf` arrived as the concept `Factura_15_03_2024`, matched nothing, and took the mtime, which for a document downloaded that day is today. Every other common shape missed the same way: `2024_03_15`, `IMG20240315123456`, `Recibo20240315`, `15032024`. New `util.dates_from_text` reads all of them, in order of appearance, and the mtime fallback is gone.
- A date whose field order the filename does not settle is no longer guessed. `03_04_2024` is 3 April in most of the world and 4 March in the United States, and nothing in the name says which; MiAZ now declines to read it rather than picking one and being wrong half the time. A year-last date is read only when one of its two leading numbers is over 12, which leaves a single possible reading. Two-digit years are declined for the same reason, and years outside 1900 to 2100 are rejected, which is what keeps `DNI_12345678A` or an IBAN from being read as a date.
- The date in a document's own metadata is finally read. `filename_guess_date` was meant to fall back to the PDF `/CreationDate` and to image EXIF, but both probes were `from pypdf import PdfReader` and `from PIL import Image` behind `except ImportError: return ''`. Neither library is a dependency of MiAZ and neither is in the external-libraries venv, so on every normal install both branches returned nothing and the date fell through to the file mtime, without a word in the log. An invoice whose PDF metadata said January 2025 was offered as the day it was downloaded. New `util.dates_from_metadata` reads it with no third-party library at all: the raw bytes are scanned for `/CreationDate (D:YYYYMMDD…)` and for `<xmp:CreateDate>`, and only when that finds nothing are Flate streams inflated and scanned, which is where an XMP-only PDF keeps its packet. Images get the same XMP scan plus an EXIF `DateTimeOriginal` read that walks the TIFF block directly. Word, Excel and OpenDocument files are read too, since both formats are ZIPs carrying the creation date in one XML member. `/ModDate` is not a creation date and is not read; when a PDF carries several creation dates, as an incrementally updated one does, the earliest wins. On a large repository this reads a real date for the great majority of documents that previously all took the mtime, at under 2 ms per document. Metadata remains a claim by whatever wrote the file: an office document made from a template inherits the template's date, so the rename preview still shows every date before it is applied.
- `util.filename_get_creation_date` is now `util.filename_get_modification_date`. It reads `st_mtime`, so the old name claimed something the code never did, and `filename_guess_date` ending its chain there is exactly how every document without a date in its name came to be filed under the day it was imported. The method has no callers left; `dates_from_metadata` is what answers "when is this document dated". A plugin calling the old name will now fail loudly instead of quietly getting a download date.
- The document's metadata is now read before its name, not after. A filename is not a reliable place to find a date: invoice numbers, policy numbers and national IDs are digit runs that pass every shape check a date parser can apply. an invoice number like `RG240719880042` contains `24071988`, which reads as a valid 24 July 1988, and a national identity number often begins with the holder's date of birth. A field named `CreationDate` cannot fail that way, because it holds a date or holds nothing. Measured against a large hand-filed repository, the metadata date agreed with the owner's own choice almost twice as often as the filename did, and where the two disagreed the metadata was right more often than not. The name is still read whenever the file carries no date of its own.
- When no date can be read, MiAZ writes `99991231` and says so, rather than passing the file date off as the document date. It is a real date, so the entry validator, the calendar and the sort order need no special case, and it sorts last, so documents whose date is unknown group at the end of the workspace instead of hiding among documents genuinely filed that day. The mass-rename Date dialog now reports how many dates it read against how many files it was given, which is what tells a working detection from one that found nothing.
- The single-document rename dialog can ask for the date. It was read once, in `set_data`, and only when field 0 arrived empty, so there was no way to request it afterwards: not for a document already filed under a wrong date, and not after correcting the concept. The date row has a detect button that reads it again from the concept as it currently stands, so editing the concept and clicking detect works.
- Plugins now unload completely and start clean the next time. The workspace menu is rebuilt whenever plugins change, and the rebuild used to clear every loaded plugin's `started` flag and call its `startup()` again: each plugin ran its whole setup once per load or unload of any other plugin, adding another gesture to the column view, another probe of the scanner, another handler each time. One of those extra gestures is what made a right click crash after `MiAZColumnVisibility` was disabled. Menu contributions are recorded when they are made (`PluginMenuRegistry`, new `plugin.install_menu_submenu()`, and `install_menu_entry()` taking an explicit category), so the rebuild replays data and `startup()` runs once per activation, as its name says.
- A plugin can no longer add to the interface after it is unloaded. `plugin.is_active()` goes false before `do_deactivate` runs, and every contribution helper (menu entry, submenu, workspace page, sidebar widget, header bar widget, sidebar dropdown, document tab) returns early when it is false. `MiAZAutoScan` builds its source menu when the scanner answers, which is easily after the user disabled it: those entries appeared anyway and did nothing until the next rebuild removed them.
- Notes' Backup and Restore entries survive a menu rebuild. They were appended straight into the Data Management menus, which no rebuild knew about, so they disappeared the first time any plugin was enabled or disabled.
- The projects file cannot be emptied by a repository mismatch any more. `MiAZProject.check()` drops the assignments of documents it cannot find; finding none of them while the repository directory is full of documents means the service and the workspace disagree about which repository is open, not that the repository is empty, so it now refuses, names both paths in the log and changes nothing. `save()` refuses to write when the configuration directory it was built for is not the active one, which stops a cross-repository write at the write itself. A repository whose documents really were deleted is still cleaned, a single missing document is still removed, and a save during shutdown still goes through. This is the failure that emptied a real repository's projects on 14 August, moving every document into the default bucket. Covered by `tests/test_projects_guards.py` (14 tests, four of them driving the real service against temporary repositories).
- `app.set_service(name, service)` registers, replaces, or with `None` removes. It used to keep the first service registered and ignore every later call, so a service could never be taken away: disabling `MiAZProjectMgt` left its `Projects` service in place, still connected to the three file signals and still writing `projects.json`. Worse, that object holds the path to one repository's `projects.json`, and a repository switch (which unloads and reloads every plugin) re-adopted it, so project assignments went to the repository the user had switched away from. The service is disposed and removed on deactivate, and a fresh one is built per activation. The console application already behaved this way; the two now agree.
- A repository whose directory is gone is reported instead of being recreated empty. `setup()` called `init()` whenever `.conf` was missing, and `init()` runs `os.makedirs`, which creates the whole path: renaming, moving or unmounting a repository directory made MiAZ rebuild it, empty, exactly where the documents used to be, with fresh empty configuration files and no message. It now refuses to create a repository directory that does not exist, and a dialog names the repository and the missing path and says nothing was changed. Creating a repository still works, since the assistant already requires an existing folder. Found by checklist item 8.5.
- Right-clicking the workspace no longer crashes when `MiAZColumnVisibility` has been deactivated. Its gesture can outlive the popover it opens (a repository switch now unloads and reloads every plugin), so `self.popover.popdown()` ran on `None`. The handler returns when there is no popover, and the teardown clears the gesture and the column view it was attached to.
- The date field in the rename dialog says when a date is not one. Typing `20261301` was refused correctly, but the label beside it kept showing the last date that parsed, so a valid, unrelated date sat next to the field and read as if MiAZ had picked one. It now reads "not a date". The calendar also stops writing back into the field while the field has the focus, so a half-typed date cannot be replaced mid-edit.
- The manage window next to a restricted field is populated every time. `manage_resource` received a view built once, when the button was connected, and the first window took ownership of it: from the second click the window came up empty until the rename dialog itself was closed and rebuilt. It takes the class and builds a live view per click; an instance is still accepted and unparented first.
- MiAZNotes: the Add note button works on the first press. It loaded the draft and then cleared the selection, and clearing fires the handler that empties the editor and disables it, which wiped the draft that had just been loaded. The selection is cleared first.
- MiAZProjectMgt: unassigning names the projects the documents left. `Ctrl+Shift+P` removes a document from every project it belongs to and reported only a count, so the user could not tell what had just been undone. `_remove_nosave` and `remove_batch` return the project names and the toast lists them.
- `F1` opens the keyboard shortcuts window. It was listed there as Help and bound to nothing: the menu item that carried it had been commented out.
- A workspace scan started before a repository switch is discarded when it arrives, instead of being applied to the repository that is now open. `_apply_parse_results` compares the directory the scan read with the current one. It showed up as an empty or short view right after switching: the stale result also spent the armed date-preset selection, leaving the new repository filtered by a range older than any of its documents.
- The repository settings window is rebuilt on a switch rather than reused, so it stops showing the previous repository's vocabularies, and the pending-documents toggle is connected once instead of once per switch (its handler ran as many times as repositories had been opened).
- `~/.MiAZ/var/tmp` is emptied on every startup. Nothing ever deleted it, so scans waiting to be imported, half-built exports and unzipped bundles piled up there: a normal installation had months of copies of documents already filed in the repository, taking up disk for nothing. The new `clean_temp_dir()` in `MiAZ/backend/util.py` removes the contents and keeps the directory, then startup recreates the subdirectories the environment declares under it (`LPATH['REPO']`). It runs after the single-instance lock is taken, so a second process starting up can never delete files the running one is using, and an entry it cannot remove is logged and skipped rather than stopping the application from starting. A symlink is unlinked without touching its target. Covered by 4 new tests in `tests/test_util.py`.
- Files added or deleted outside the app stopped reaching the workspace after switching repositories, until a restart. `MiAZWorkflow.switch_finish` built a new `MiAZWatcher` on every switch and registered it as the service, but `MiAZWorkspace` connects to the watcher once, when it is built, so from the second repository onwards it was listening to a deactivated object. The switch now re-points the existing watcher with `set_path()`, which rebuilds its file monitor, so the service identity and every connection to it survive. Found by the new UI suite on its first full run.
- Deleting a document from the rename dialog now goes through `util.filename_delete` instead of calling `os.unlink` directly, so the `filename-deleted` signal fires. Without it the workspace and the new document index both kept an entry for a file that was already gone, until the next full re-scan. Found by the new boundary test, which is the only violation of that rule in the tree.
- A failed workspace scan no longer leaves the application stuck. `update()` sets the status to `BUSY` and only `_apply_parse_results` cleared it, so an exception in the worker thread left the app busy for good: every later update logged "App is busy. Workspace update deferred" and rescheduled itself, forever, with the thread already dead and nothing in the log to say why. The scan now runs through `run_in_background` with an `on_error` that logs the failure and releases the status.
- A deleted file that was not in the view no longer decrements the document counter. The old incremental handler removed unconditionally, so the count could drift below the real number until the next full scan.

### Changed

- A plugin adding a workspace page no longer has to clean up after itself. `MiAZWorkspace.remove_stack_page` removes the child instead of hiding it, so the name is free again and a re-activated plugin just builds a fresh page. `add_stack_page` replaces any other child holding the same name rather than silently showing it. `MiAZNotes` dropped both halves of the workaround: the branch that looked for a hidden page by name and adopted it, and the block that hid the page on deactivate. `AGENTS.md` documented that dance as a rule every page-adding plugin had to follow; it now documents the opposite.
- `MiAZStatus` now means one thing. It was doing three jobs through one process-wide flag: "a repository is being switched" (`MiAZWorkflow`), "a workspace scan is in flight" (`MiAZWorkspace.update` set it and `_apply_parse_results` cleared it), and "a plugin is doing bulk work, hold the refreshes" (four plugins). `BUSY` now only means the first; the scan re-entry guard is a private `_scan_in_flight` on the workspace, and the plugins take a handle from `suspend_updates()`. `MiAZAddFromDir`, `MiAZImportFromZip`, `MiAZOCR` and `MiAZAutoScan` no longer import `MiAZStatus` at all.
- Three background workers moved onto `run_in_background`: the workspace repository scan, the external-libraries venv install and the `MiAZInsights` page rebuild. Each dropped its own try/except-and-log wrapper.
- Every remaining background task now runs through `run_in_background`. The eight raw threads left in the plugins are gone: `MiAZAddFromDir` (the directory import), `MiAZImportFromZip` (the ZIP import), `MiAZAutoScan` (scanner-source detection and the scan itself), `MiAZOCR` (the OCR run) and `MiAZAIAssistant` (the suggest call, the chat text extraction and the chat request). Workers that ended in `GLib.idle_add(callback, ...)` now return their result and let `on_done` marshal it, so `_finish_import`, `_finish`, `_build_source_menu`, `_set_document` and `_on_answer` are ordinary methods again rather than idle callbacks returning `False`. Two threads stay raw on purpose and now say why in a comment: `webserver.py` runs a serve loop rather than a task, and `util.check_remote_directory_sync` starts a thread only to join it with a timeout.
- `MiAZImportFromZip` disables the file watcher on the main loop before its worker starts, instead of as the worker's first statement. There was a window where the watcher was still live and reacting to the files being copied.
- `MiAZConfig`'s `used-updated` and `available-updated` now carry the set of keys that changed, instead of nothing. `save()` diffs what it is about to write against what is on disk, which is the only version that survives `set()` mutating the cached dict in place. `None` means the previous contents could not be read, so the receiver must assume everything changed. The workspace uses it to drop one description-cache entry (`index.invalidate_cache(config, key)`) rather than the whole cache: renaming one country used to make every document in the view rebuild all six of its field descriptions. Handlers that only repopulate a dropdown ignore the payload through the new `actions.dropdown_repopulate` adapter, so `dropdown_populate` keeps its signature for its many direct callers. Covered by 9 new tests in `tests/test_config.py` and 8 in the new `tests/test_config_cache_invalidation.py`.
- The workspace filter moved out of the widget into `DocumentQuery`. `_refresh_filter_cache` now builds a query (`_read_query`) instead of copying widget state into eight `_cached_*` attributes, and `_do_filter_view_main` is one line: `return self._query.matches(item)`. The five `_do_eval_cond_matches_*` methods and the `self.datetimes` memo are gone; date parsing is an `lru_cache`d module function in `query.py`.
- The core filter no longer knows MiAZProjectMgt exists. It used to look up `plugin-MiAZProjectMgt-dropdown` by name and override two of its own conditions when a project was selected. The plugin now registers a query hook that sets `ignore_date` and `ignore_active` itself. The `register_filter_view` hook it already used could not express this, because it ANDs conditions and this one has to relax them.
- The document parse moved out of `MiAZWorkspace` into the new index. It used to exist twice inside that 1398-line widget, in `_parse_files_worker` (full scan) and `_build_item_for_file` (single file), with the same seven-field loop, cache lookup and config validation written out separately in each. The two had already drifted: the full scan batched cache updates and built a field index, the incremental one wrote the cache directly and refused any document whose name was not fully valid. Both now call `MiAZDocumentIndex.build_item`, and `tests/test_index.py::test_incremental_and_full_scan_agree` keeps them honest. `workspace.py` drops from 1398 to 1211 lines.
- The workspace no longer writes `util._field_index` from a re-scan of its own; `_apply_parse_results` hands over `index.field_index()`, which the scan has already built.
- The concept vocabulary the rename dialog completes against (`ENV['CACHE']['CONCEPTS']`) is now refreshed on single-file changes too, through `_publish_concepts`. The old incremental path never updated it, so after adding or renaming a document the dialog kept offering concepts from the last full scan.
- `MiAZWorkspace.initialize_caches` and `_on_application_finished` now read and write the index cache instead of a private copy on the widget.

### Fixed

- The .rpm and the .deb pass policy checks and now carry the same payload. The .deb had been shipping 94 `.pyc` files compiled by the Fedora build host's CPython 3.14, which Debian never loads, and was missing the `copyright` and `changelog.Debian.gz` files Policy requires: the cross-distro build path uses plain `dpkg-deb`, so debhelper never ran. The .rpm shipped `/usr/share/doc/miaz/README` as a dangling symlink, since `%doc` stored the repository root symlink rather than its target, and gave its own `%changelog` a version it disagreed with, because the build counter was written into `Version:` instead of `Release:`. RPM artifacts are now named `miaz-0.1.50-13.fc44.noarch.rpm`, with the release version in `Version:` and the build counter in `Release:`, which is what that field is for. Across both packages, 99 library modules carried a shebang while being mode 0644, two of them naming `/usr/bin/python`, a path Debian does not have, and `/usr/bin/miaz` was installed group-writable. New `miaz.rpmlintrc` documents the two rpmlint tags that do not apply to a noarch package with no ELF objects.
- Every package is built from one export of one commit, so the `.rpm` and the `.deb` of a run always declare the same version and carry the same files. They did not before: the `.rpm` took its sources from `git archive HEAD` but its spec and version from the working tree, and the `.deb` took everything from the working tree, so the two could disagree about their own version and about which files they shipped. New `scripts/packaging/lib/source_export.sh` exports the commit once; `create_rpm.sh` and `create_deb.sh` read sources, `miaz.spec`, `debian/*` and the version from that export, and `build_all.sh` hands both formats the same one. It accepts `--pushed` (fetch, then the last commit pushed to the tracked branch) and `--ref REF` (any tag, branch or SHA), defaulting to `HEAD`. The export prints what it is building and warns when uncommitted files are being left out. Two consequences: the package version now comes from the commit rather than the working tree, so a build-counter bump reaches a package once it is committed; and a build no longer writes anything into the repository, since staging and build directories live inside the export.
- New `scripts/checks/verify_packages.sh` checks a built `.rpm` and `.deb` without installing either. Structure and payload run natively (metadata, dangling symlinks, compiled bytecode, desktop file, AppStream metainfo, GSettings schema, shebangs on non-executable modules, raster images in scalable icon directories, syntax); `lintian` runs in a podman or docker container when it is not installed; and `apt-get install --simulate` against `debian:stable-slim` and `ubuntu:24.04` proves the `Depends` names exist in the target release, which is the one thing static inspection cannot do. It also diffs the two payloads against each other, which is what caught the bytecode only the .deb carried. `build_all.sh` runs it with `--no-container` and fails the build on a regression.
- The rename dialog's **Rename** button is insensitive while the fields cannot make a valid filename, instead of looking clickable and doing nothing. `_on_rename_response` refused the rename and focused the offending field, which is invisible when the field is already on screen, so the button read as broken. `MiAZRenameDialog` emits a new `fields-changed` signal from `_on_changed_entry`, and the dialog enables the response from `is_valid()`. Date, Country, Sent by, Concept and Sent to are the blocking fields; Group and Purpose stay advisory (a warning in the live preview). A document whose stored values are not in the repository configuration opens with those dropdowns on "Any", which is now visible in the button rather than only in the row colours.
- Dialog bodies no longer open with all their text highlighted. The body label of every dialog is selectable so an error message or a path can be copied, and a selectable `Gtk.Label` selects everything the first time it takes the focus, which is what the dialog does while opening: the rename confirmation came up with "You are about to rename this document. Are you sure?" fully selected. A focus controller drops that first selection, one idle later so it lands after the select-all, and removes itself; selecting by hand is untouched.
- A failed background operation no longer freezes the workspace for the rest of the session. `MiAZImportFromZip`, `MiAZAutoScan` and `MiAZOCR` each take an update-gate handle before starting their worker and release it in the callback that reports the result. An exception outside the worker's own try block killed the thread silently, so the handle was never released, the view stopped refreshing and every later update was swallowed with nothing in the log. `MiAZImportFromZip` had one waiting: `get_temp_dir()` ran after the watcher was disabled but before the `try`. Each of them now passes an `on_error` that releases the gate, re-enables the watcher and reports the failure.
- `MiAZAddFromDir` reports a directory import that stopped early instead of ending in silence.
- `MiAZAutoScan` still installs its Add-menu entry when scanner detection fails. Detection ran in a thread whose only job was to build that menu, so an exception left the plugin with no entry at all: no way to scan and no hint that anything had gone wrong. A failure now installs the plain entry, which reports the real problem when used.
- The AI assistant's "Suggest with AI" button no longer stays greyed out reading "Thinking…" after an unexpected failure, and the chat no longer waits forever for an answer that will not arrive. Both had error handling that covered the provider call but not the code around it.
- The **"Since last year"** date filter covered the wrong period. It resolved through `util.since_date_this_year`, which returns 1 January of the current year, so the label said "last year" while the range was the calendar year to date: seven months on 7 August, and two days on 2 January. It now uses `since_date_last_n_months(now, 12)`, the last twelve months, consistent with its "Since last 3 months" and "Since last 6 months" neighbours. The same window was wrong in `MiAZInsights`, which mirrors the same preset list, and is fixed there too so the two views agree.
- Lint is clean again: `ruff check MiAZ data/resources/plugins tests` reported three unused imports. `timedelta` in `backend/util.py` and a stray `pytest` in `tests/test_boundaries.py` were removed. The third, `make_usage` in the AI plugin's `suggestion.py`, is a deliberate re-export that `tests/test_ai_plugin.py` asserts on, so it is now declared in `__all__` instead: applying the fix ruff suggested would have deleted it and broken that test.
- The `MiAZFullscreen` button now comes back after the plugin is disabled and re-enabled. `do_deactivate` detached the button from the header bar but left it registered under `headerbar-togglebutton-fullscreen`, so the next activation looked the key up, found the detached button, took that as "already set up" and skipped the whole block. The button was gone for the rest of the session. Widget keys are now unregistered along with the widget.
- Disabling and re-enabling `MiAZNotes` no longer leaves the "All notes" page wired to the previous plugin instance. The page was kept in the stack and re-adopted by the new instance, which reassigned `store`, `backup` and the two compute callbacks but not `on_open_document`. That callback stayed bound to the deactivated instance, so opening a note from the page called into a plugin that was no longer running, and the dead instance could never be collected. The page is now rebuilt, so every callback belongs to the live plugin.
- Workspace pages of an uninstalled plugin no longer stay in the `Adw.ViewStack` for the rest of the session as hidden children.
- Two overlapping background operations no longer let the first one to finish re-enable workspace refreshes for both. Every setter of the old `MiAZStatus.BUSY` flag reset it unconditionally, so starting an OCR run while an AutoScan import was still going meant the remaining work refreshed the view on every file, which is what the flag existed to prevent. The reference-counted gate stays shut until the last holder releases. `MiAZAutoScan` could also release twice (its `finally` block and `_on_scan_error` both ran on a failed scan); the handle makes the second release a no-op instead of an unbalanced reset.
- Switching to a repository no longer reads configuration left behind by a previous one. `MiAZConfig.cache` was a class attribute, shared by every config instance in the process and keyed by absolute filepath. Sharing was deliberate (SentBy, SentTo and Person all read `people-available.json` and must agree), but it tied the cache lifetime to the process instead of the repository: `repository.load()` built eight new config objects per switch while the old entries stayed, so a repository edited outside MiAZ, or simply switched away from and back to, was read from the stale copy. The cache now belongs to the `MiAZConfigStore` of one repository and is emptied when that store is disposed. Two of the new tests fail against the previous code.
- `MiAZConfig.set()` no longer writes its cache bookkeeping to the wrong key. It called `save()` with no filepath; `save_data` resolved the default and wrote the correct file, but the cache invalidation and the signal check both saw the empty string, so `self.cache['']` was marked dirty, the real entry was left looking clean, and `used-updated` never fired. It worked only because `load()` returns the cached dict by reference and `set()` mutates that same object: any caller saving a freshly built dict would have read stale config afterwards. `save()` now resolves the default before doing either.
- `MiAZConfigApp.save()` now invalidates the cache. It overrides `save()` to emit `repo-settings-updated-app` instead of the base signals and skipped the cache bookkeeping entirely. This is the config that records the active repository, so it sits on the switch path.

Every repository needs a way to add its first document, so that action should not live behind an optional, disableable plugin; a fresh repository previously had to hardcode it into its default `plugins-used.json` to avoid shipping with no way to add documents at all, which is no longer needed now that the feature cannot be disabled. The headerbar "Add" menu (`headerbar-add-menu`) now always shows the core action first, followed by any loaded Import-subcategory plugin (`MiAZAddFromDir`, `MiAZImportFromZip`, `MiAZImportFromScan`), and the Add button is now always visible instead of only when an Import plugin happened to be enabled.
- The workspace no longer opens on an empty view when the default date filter has no documents. Right after a new month starts, "This month" is usually empty; the workspace now selects the nearest date filter that actually contains documents (walking to wider windows: "Since past month", "Since last 3 months", and so on, falling back to "All documents"). It runs only as the initial default, at load, repository switch, and the day/month rollover, and never overrides a date filter you selected by hand. The chooser (`pick_date_preset` in `widgets/workspace.py`) is covered by `tests/test_workspace_datepick.py`.
- The rename dialog is now keyboard-friendly. It focuses the first field that needs attention when it opens, the date is an editable `YYYYMMDD` entry (the calendar remains as an assist), `Ctrl+Enter` applies from any field and `Esc` cancels, and in the concept entry `Enter` picks the highlighted autocomplete while the popover is open. Applying now refuses to build an invalid filename: when a required field (date, country, sent by, concept, sent to) is missing or invalid the dialog stays open and focuses the field to fix.
- Merged the `MiAZAIChat` plugin into `MiAZAIAssistant`. There is now a single AI plugin that offers both features: suggesting the seven filename fields from a document (the `Suggest filename…` menu entry and the rename-dialog button) and chatting about the selected document (the `Chat with document…` menu entry). Both share one provider layer and one settings dialog, so API keys and the active provider are configured once. Internally the `miazaic` package was folded into `miazai`: every provider (Claude, OpenAI, Gemini, Ollama) now implements both `suggest()` and `chat()` on a shared base, `make_usage` has a single definition in `miazai/usage.py`, and the chat dialog moved to `miazai/ui/chat.py`. No configuration is migrated, so anyone who had configured the old `MiAZAIChat` plugin re-enters that provider's API key once. The aggregated `data/resources/plugins-requirements.json` no longer lists `miazaichat`. Covered by `tests/test_ai_plugin.py`.
- Three workspace-view efficiency fixes from a performance review (`responses/2026-08-04-workspace-view-performance-analysis.md`), none of them behavior changes. (1) The workspace Type column no longer stats the file on disk to pick its icon: `Gtk.ColumnView` rebinds a cell every time its row scrolls back into view, so the old `MiAZIconManager.get_mimetype_icon` (`os.path.exists` + `Gio.File.query_info` per bind) repeated that disk I/O on every scroll. It is replaced by `get_mimetype_icon_for_extension`, which resolves the icon from the extension alone via `Gio.content_type_guess` and caches it, no filesystem access at all. (2) `_parse_files_worker` built the field-value index (used by "how many documents use this Country/Group/…") in a second full pass over the file list that recomputed `util.get_fields()` for every file from scratch; it is now folded into the existing parse loop, which already has those fields in hand. (3) The workspace filter's project-dropdown bypass check (used when `MiAZProjectMgt` has a project selected) looked up the dropdown widget and its selection on every item on every filter pass; it is now resolved once per pass in `_refresh_filter_cache`, alongside the other cached filter inputs, and read from `self._cached_project_bypass`.
- Four more workspace-scan efficiency fixes, benchmarked against a large real repository. The biggest one: Country/Group/Purpose/SentBy/SentTo display labels are now cached per (field, raw value) in `self.cache`, the same way the Date label already was; only `humanize_value()` (a gettext lookup) was uncached, and re-running it for every field of every document on every scan measured at 122.78ms there, dropping to 0.32ms once cached (values repeat heavily across real documents: a handful of distinct countries across the whole repository). The cache is invalidated by the same `used-updated` signal that already resets it, so edited vocabulary still shows up correctly. Also: `util.get_files()` now lists the repository with `os.scandir()` instead of `glob.glob()` + a separate `os.path.isfile()` stat per entry (7.66ms to 1.53ms); the parse loop's own `fields = util.get_fields(filename)` is reused instead of calling `filename_validate()` right after (which re-parsed the same filename from scratch); and the workspace's default Date column sort uses a dedicated comparator with no `.upper()` call, since a `YYYYMMDD` value has no case to fold, while every other sorted column (group, purpose, sender/recipient labels, concept) keeps its case-insensitive compare since those can hold real mixed-case text. Measured together, a ~224ms workspace-update time is expected to drop to roughly 90-100ms; the remaining time is the `MiAZItem` GObject construction and GTK's own model/view work, both inherent to the `Gio.ListStore` architecture.
- The "Review" toggle triggered two full workspace rescans per click instead of one. `show_pending_documents` calls `sidebar.clear_filters()`, which itself calls `workspace.update()`, and then separately reselects the Date dropdown to "All documents", whose selection signal independently calls `update()` again. The second reselection now blocks that signal (the same `handler_block`/`handler_unblock` pattern already used in `_update_dropdown_date` and `_auto_select_date_preset` for the same purpose), so toggling Review still shows every date range, but scans the repository once instead of twice.
- MiAZNotes' "All Notes" view now defaults its status filter to "All statuses" instead of "In Progress", so it opens showing every note rather than hiding done/planned ones by default.
- The `"Workspace updated in {dt}s"` debug log now includes the document count: `"Workspace updated in {dt}s ({n} documents displayed)"`, `n` being the count after the active filters are applied, not the repository total. The log line moved from `_apply_parse_results` (end of the background parse, before the store is spliced or filtered) to `_idle_view_update` (after `view.update()` applies the splice, when `self._num_displayed_items` is the real post-filter count), so the timing now also covers the store splice and filter pass, not just the parse.
- Incremental workspace updates for large repositories. A single file change (add, delete, rename) no longer re-scans and re-parses the whole repository; it updates just the affected row. The watcher now forwards the changed path and event through a new `repository-changed(path, other, event)` signal (coalescing a burst to one settled event per path, and falling back to a full `repository-updated` when more than 25 files change at once). The workspace applies the change with the columnview's `update_incremental` primitive and a `_build_item_for_file` helper that mirrors the full parse. The existing full re-scan (`repository-updated`) is kept as the safety net for the Notes plugin and for anything the incremental path does not confidently handle (pending or invalid names, unknown events); a skip flag suppresses that re-scan only when the per-file update fully applied the change. Because the fallback does a complete splice-replace, an imperfect incremental update can never corrupt the list, only cost a redundant re-scan. Covered by `tests/test_watcher.py` (7 tests). This turns the common single-document case from O(N) to roughly O(1); bulk changes still take the full path.
- GNOME HIG polish (P1 batch). The sidebar's "Search in all fields" and concept search now use `Gtk.SearchEntry` instead of a bare `Gtk.Entry`, so they get the search icon, a clear button and Escape-to-clear (the config selector already used `Gtk.SearchEntry`). Label typography in `services/factory.py` moved from manual Pango markup to theme-correct CSS classes (`heading`, `caption`, `dim-label`) and, importantly, the dropdown and column-view cell labels now use `set_text(item.title)` instead of `set_markup`, which removes a real markup-injection risk for values containing `&`, `<` or `>` (a company name, a concept). The "No documents found" status page dropped its redundant `<big>` markup wrapper. The keyboard-shortcuts UI was migrated from the deprecated `Gtk.ShortcutsWindow` (deprecated since GTK 4.18) to `Adw.ShortcutsDialog` (libadwaita 1.8+, present at the GNOME 50 floor), which also removed the inline builder XML in `services/actions.py` and the now-unused `services/help.py`.
- Accessibility: the icon-only buttons in the configuration selector (`frontend/desktop/widgets/selector.py`) now have tooltips: Add, Remove and Edit on the available side, Edit on the used side, and Enable/Disable on the transfer controls. The Enable/Disable tooltips were also hardcoded English strings (`'enable'`/`'disable'`); they are now translatable. A broader accessibility audit stays on the 0.2.x backlog.
- CI (`.github/workflows/ci.yml`): the test job now runs a Python matrix (3.11 and 3.12), lints `tests/` in addition to `MiAZ` and the plugins, and reports coverage (`pytest-cov`, informational). 3.9/3.10 compatibility is enforced statically by ruff's `target-version = "py39"`, since the system PyGObject bindings follow the runner's Python and cannot be matrix-tested against pip.
- Clarified the backend architecture rule in `AGENTS.md`: the backend forbids GTK/Adw/Gdk widget imports, but `GObject`/`GLib`/`Gio` are allowed and used on purpose, since the backend exposes its events through GObject signals (the backend/frontend contract). The old "zero GTK imports" wording read as a violation when it was the intended design.
- The Flatpak manifest `flatpak/io.github.t00m.MiAZ.json` now builds the `miaz` module from local sources (`"type": "dir", "path": ".."`) instead of cloning a pinned `github.com/t00m/MiAZ.git` branch (`0.1.26`). The build now uses whatever version `meson.build` declares, so there is no version string to keep in sync in the manifest. Both Flatpak manifests (`.json` and `.local.json`) now build from the local tree.

### Deprecated

- Flatpak packaging is deprecated on purpose and no longer built by default. A Flatpak runs sandboxed on `org.gnome.Platform`, which cannot see or run the host command line tools that plugins depend on (`ocrmypdf` for OCR, `scanimage` for the scanner), so those features never work in a Flatpak build and users saw "OCR tools not installed" even with the tool present on the host. MiAZ is a native desktop app; use the deb, rpm or AppImage package instead. The Flatpak build code is kept for reference and is gated behind `MIAZ_ALLOW_FLATPAK=1` in `build_all.sh` and `create_flatpak.sh`.

### Removed

- Dropped the `MiAZNewspaper` plugin and everything tied to it. It rendered the documents visible in the Workspace as a "MiAZ Times" broadsheet published to the Browser page, but every sentence on that page was generated from the seven filename fields the Workspace columns already show, so it produced no information the user did not have. Its costs were real: 36 translatable messages (out of 885) in the hardest register to translate, prose hardcoded to the default purpose codes (`INV`, `REQ`, `STM`, `INF`, `CON`, `TKT`) so any renamed purpose fell back to a generic sentence, a full `rmtree` plus a recopy of 244 KB of web fonts on every filter and sort change, and 275 lines of `templates/*.html` design mockups that no code ever read. It also declared `Dependencies: HelloWorld`, a leftover from templating off the demo plugin, which silently enabled HelloWorld whenever the newspaper was enabled. Removed: `data/resources/plugins/MiAZNewspaper/`, its `po/POTFILES` entry, and its 36 messages from `po/miaz.pot`, `po/es_ES.po`, `po/de.po` and `po/fr.po` (885 to 849 messages, all four in sync, all compile). `MiAZInsights` (formerly `MiAZYearReport`) is now the single reference example for the WWW-publish + Browser-page pattern in `AGENTS.md`, and it earns the pattern by aggregating (counts, heatmap, rank movers, country map) instead of restating. Bundled plugin count is now 19. Historical release notes in `CHANGELOG.md`, `debian/changelog` and `metainfo.xml.in` still name the plugin on purpose; those record what shipped at the time.
- Removed the per-repository change journal (`MiAZHistory`, `backend/history.py`, service `history`). It appended every add, rename and delete to `<repo>/.history/<YYYYMM>.jsonl`, but nothing read it back and the feature was unused, so it was dropped along with its `app.py` service registration and its tests. MiAZ is a curated tool for a small set of documents, not an archive of record, so change tracking, undo and recovery are not part of its scope. Git-based repository tracking may return later as an optional `MiAZGit` plugin. The `filename-imported` signal and the `origin` provenance argument on `util.filename_import`, which existed only to feed this journal, were removed as well: `filename_import(source, target)` now just copies and emits `filename-added`, and the ZIP and scan importers no longer build provenance objects.
- Removed two unused GSettings keys, `sidebar-width` and `last-repository`, from `data/io.github.t00m.MiAZ.gschema.xml`. Nothing read or wrote them. The sidebar lives in an `Adw.OverlaySplitView` (fixed 300-360 px range, no user-draggable resize), so there is no sidebar width to persist; and the active repository is already restored from the App JSON config `current` key, so a second GSettings copy would only add a competing source of truth. Removed now, before 0.2 freezes the schema. The Countries configuration keeps its add/remove/edit buttons hidden by design (countries are a fixed ISO 3166-1 vocabulary with bundled flag icons); the stale `FIXME` there was replaced with a rationale comment.

### Fixed

- Plugin icons never showed up anywhere, because `MiAZPlugin.get_source_dir()` looked for a folder named after the plugin's `Module` (`projmgt`) while plugin folders are named after its `Name` (`MiAZProjectMgt`). For most bundled plugins it therefore returned `None`, so `get_icon_path()` found nothing and every caller silently fell back to no icon, including the sidebar filter rows in MiAZProjectMgt and MiAZPeriodicity. It now tries `Name` first and `Module` second, in the system directory then the user one.
- Opening the rename dialog only to set a plugin value (a project, a periodicity) and pressing Rename showed "Another document with the same name already exists" and lost the edit. With no filename field touched there is nothing to rename, and `util.filename_rename` returns `False` both for "nothing to do" and for "the target already exists", so the dialog reported a name clash and never committed the tab edits. It now checks whether a rename is due first: when it is not, it skips the confirmation, writes the tab edits against the unchanged name, shows a toast and closes. When a rename is due, nothing changes.
- The "Suggest with AI" button from MiAZAIAssistant could appear several times in the rename dialog. `inject_suggest_button` connected a new `rename-dialog-built` handler on every call but tracked only the latest handler id, so any repeated call leaked the earlier handler and stacked another button on every rename. The injection is now idempotent: it disconnects any previously installed handler before connecting a new one, and clears its tracking slot on removal, so exactly one button is installed no matter how many times it runs.
- Plugins that rely on system command line tools no longer fail with a "tools not installed" error when MiAZ is launched from the GNOME desktop icon rather than a terminal. A desktop launcher can start the app with an empty or stripped `PATH`, so `shutil.which` and subprocess found nothing (MiAZOCR reported ocrmypdf missing, MiAZAutoScan reported scanimage missing) even though the tools live in `/usr/bin`; running from a shell worked because the shell `PATH` is rich. MiAZ now appends the standard system tool directories (`/usr/bin`, `/usr/local/bin`, `~/.local/bin`, and the `sbin` variants) to `PATH` at startup if they are missing, so tool detection and execution behave the same regardless of how the app was started.
- Dialog body text is now selectable and left-aligned. The `Adw.AlertDialog` body label was read-only and centred, so a user could not copy the command or message shown in a dialog such as "OCR tools not installed". This applies to every error, warning, info and question dialog.
- The workspace date filters "Since past month", "Since last 3 months" and "Since last 6 months" excluded documents from the earliest month they should cover. `since_date_last_n_months` subtracted a fixed 30 days per month and forced the day to the 1st, which drifts at month boundaries: on the 31st of a month, 30 days back stays in the same month, so "Since past month" on Jul 31 started on Jul 1 and hid all of June (and the 3 and 6 month options were each off by a month). It now steps back whole calendar months. Covered by new tests in `tests/test_util.py`.
- The workspace date filter no longer hides documents dated today when MiAZ has been left running past midnight. The relative date presets (This month, Future, and so on) baked in the day the workspace was first loaded and were never refreshed, so once the calendar day rolled over a document dated today fell outside every today-bounded range and only appeared under "Future" (which had been defined as the old day plus one). `update()` now rebuilds the presets with the current day whenever it detects the day changed, preserving the selected preset by title (its key changes daily, so it cannot be matched by key). Same-day updates skip the rebuild, so there is no added cost in normal use.
- Disabling or uninstalling a plugin that publishes to the MiAZ Browser now removes its web content. Web cleanup moved from each plugin's `do_deactivate` into the plugin manager (`unload_plugin` calls a new `_remove_plugin_www`), which deletes `LPATH/WWW/<plugin folder basename>` for any plugin, bundled or user-space, on disable or uninstall. Previously only `MiAZNewspaper` and `MiAZInsights` cleaned up after themselves, so user plugins such as `KB4MiAZ` and `MiAZdeas` left their published directories behind and they kept showing in the Browser. The duplicated `rmtree` in the two bundled plugins was dropped. A plugin that publishes under a name different from its folder is not covered centrally and must still clean up in its own `do_deactivate`.
- The MiAZNotes plugin failed to load from the rpm (and any `git archive` based package) with `ModuleNotFoundError: No module named 'lib'`. The plugin keeps its own code in a bundled `lib/` subpackage (`data/resources/plugins/MiAZNotes/lib/`), but `.gitignore` had an unanchored `lib/` rule (from the standard Python template, meant for a build directory at the repo root) that matched that path at any depth. The subpackage was therefore untracked and excluded from the `git archive HEAD` source tarball, so the installed plugin had `notes.py` but no `lib/`. Anchored the rule to `/lib/` and `/lib64/` so it only ignores a repo-root build directory, not nested plugin source. The `MiAZNotes/lib/` files must now be added to git so they ship. This was a packaging problem, not a missing third-party dependency.
- Config and repository JSON is now written atomically. `MiAZUtil.json_save` and the repository bootstrap (`repository.py` `init` / `_init_default_plugins`) share a new module-level `atomic_json_save` (`MiAZ/backend/util.py`) that writes to a temporary file in the same directory, `fsync`s it, then `os.replace()`s it onto the target. A crash mid-write can no longer leave a half-written `repo.json`, `plugins-used.json`, or config file.
- The disaster-recovery restore paths (`MiAZ/backend/dr.py`) no longer risk masking the real error or crashing during rollback. `restore_config` and `restore_repository` define the `.old` sidecar path before the `try`, so a failure in `unzip` (before anything is moved) rolls back cleanly instead of raising `NameError`. The rollback is wrapped so a rollback failure is logged rather than replacing the original exception, and the original error is logged before re-raising. Covered by the new `tests/test_dr.py` (8 tests: backup/restore round-trips plus both rollback paths).
- `MiAZUtil.filename_rename` no longer silently swallows the two skip cases. A rename whose target already exists now logs a warning (the caller already surfaces the skip; mass rename counts it in a toast), and a no-op rename where source equals target logs at debug. Removed the stale `# FIXME` markers; the Windows-path doubt is resolved as "Linux-only for 0.2" with a comment.
- Version numbers now agree across every static config file. `meson.build` is the single source of truth (`0.1.28+build.29`). `miaz.spec` (`Version` and `%changelog`), `pyproject.toml` (`version`), `debian/changelog`, and the AppStream `<releases>` list in `data/io.github.t00m.MiAZ.metainfo.xml.in` were stale (`0.1.26` / `0.1.1`); all now read the release version `0.1.28`. The `+build.NN` suffix is left to `meson.build` alone, since `scripts/devel/increase_meson_version.sh` auto-increments it and the packaging scripts append it to artifacts at build time.
- AI plugins used Ollama even after configuring another provider. The active provider is now inferred from the first configured provider when the selector was never changed.
- AI provider failures are shown with full, selectable, copyable details.
- The Export/Import menu button in repository settings now links visually with the neighbouring toolbar buttons.
